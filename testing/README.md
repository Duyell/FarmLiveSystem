## 二、怎么执行

### 2.1 手工用例

按 [01-功能测试用例集.md](01-功能测试用例集.md) 执行，先跑第 2 章冒烟，再按
登录 → 权限 → 基础信息 → 预约 → 调整 → 排队 → 通知 → 故障 → 统计 → 日志 → AI → 前端
的顺序做系统测试。

### 2.2 自动化脚本

```powershell
cd testing\api
python setup_env.py      # 建测试账号与专属资源（可反复执行）
python run.py            # 全量执行
python run.py --module booking      # 单模块
python run.py --id BOOK-0           # 按编号过滤
```

执行完在 `testing/reports/` 生成 Markdown 报告；有失败时退出码为 1。

### 2.3 脚本会创建什么

| 类型 | 命名 | 说明 |
|---|---|---|
| 账号 | `t_admin`、`t_live`、`t_viewer`、`t_farmer1..3` | 统一密码 `Test@1234` |
| 探针账号 | `t_must_*`、`t_pwd_*`、`t_lock_*`、`t_disabled` | 用于首登改密、改密、锁定、停用 |
| 农户 | `NFTEST01..03` | 与账号一一绑定 |
| 场地/设备 | `C900` / `ZBT-C900-01..03` | 每日 08:00–22:00，供预约类用例使用 |

每轮执行前会清理上一轮同类数据，不影响现有业务数据。
