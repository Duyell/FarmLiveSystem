## BUG-01 农户列表带关键词查询必然 500（影响搜索、筛选）

| 项 | 内容 |
|---|---|
| 严重级别 | 严重（功能不可用，不阻断主流程） |
| 影响接口 | `GET /api/admin/farmers?keyword=...`、`GET /api/live/farmers?keyword=...` |
| 影响页面 | 基础信息 → 农户列表的搜索框；按关键词筛选农户 |
| 状态 | 待修复 |
| 自动化用例 | BASE-03、BASE-07 曾因此失败，已改为不带关键词查询 |

**复现**

```powershell
# 先登录拿 token，然后：
curl "http://127.0.0.1:8080/api/live/farmers?keyword=张" -H "Authorization: Bearer <token>"
# 返回 HTTP 500 {"code":"SERVER_ERROR","message":"服务器异常，请稍后再试","data":null}
```

**原因**（`backend/src/main/java/com/farmlive/repo/AdminRepository.java`）

```java
// 第 218 行：SQL 只有 4 个占位符
where.append(" WHERE (farmer_no LIKE ? OR name LIKE ? OR county LIKE ? OR phone LIKE ?) ");
// 第 219-220 行：却绑定了 5 个参数
for (int i = 0; i < 5; i++) args.add(like);
```

报错：`Parameter index out of range (5 > number of parameters, which is 4)`。

**修复建议**：把 `i < 5` 改为 `i < 4`，并补一条「关键词搜索农户」的回归用例。

## BUG-02 不支持的请求方法返回 500，而不是 404/405

| 项 | 内容 |
|---|---|
| 严重级别 | 一般（不影响主流程，但暴露内部异常并误导调用方） |
| 影响接口 | 所有未映射的方法/路径，例如 `DELETE /api/admin/logs/1` |
| 状态 | 待修复 |
| 自动化用例 | LOG-03（断言"删除被拒绝"仍通过，但记录了 500） |

**现象**：`DELETE /api/admin/logs/1` 返回 `HTTP 500 SERVER_ERROR`。

**原因**：`GlobalExceptionHandler` 的兜底 `@ExceptionHandler(Exception.class)` 把
`NoResourceFoundException`、`HttpRequestMethodNotSupportedException` 也接住了，统一转成 500。

**修复建议**：为这两类异常单独处理（返回 404 / 405），兜底处理器只吞真正的未知异常。

## ENV-01 增量脚本缺 010 时知识库静默失败

| 项 | 内容 |
|---|---|
| 严重级别 | 严重（AI 知识库完全不可用） |
| 状态 | 本机已修复：补跑 `deploy/sql/010-knowledge-chunk.sql` 与 `013-knowledge-seed.sql` |

**现象**：后端启动日志出现

```
WARN KnowledgeService : 种子知识入库失败（不影响启动，配置 AI Key 后可重新解析）: 向量序列化失败
```

**原因**：数据库缺 `knowledge_chunk` 表（010 脚本没执行），`insertChunk` 把 SQL 异常包装成
"向量序列化失败"，看起来像编码问题，实际是缺表。

**建议**：
1. 部署/测试环境准备时，务必按 **002 → 014** 顺序执行全部增量脚本；
2. 把 `insertChunk` 的异常信息改为包含真实 SQL 原因，避免误导排查方向。
