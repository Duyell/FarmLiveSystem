# 接口自动化测试脚本

按功能模块拆分的自动化用例，共 **77 条**，直接调用后端接口（必要时查库校验），
跑完输出控制台结果和 Markdown 报告。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 后端 | 已启动，默认 `http://127.0.0.1:8080` |
| 前端 | 已启动，默认 `http://localhost:5173`（UI 模块用） |
| 数据库 | MySQL 8 可连，默认 `127.0.0.1:3306 / farm_live` |
| Python | 3.8+，只用标准库，无需 pip 安装 |
| mysql 客户端 | 造数用，默认 `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe` |

## 2. 快速开始

```powershell
cd tests\api

# 第一次（或需要重置环境时）：建测试账号 + 专属场地/设备
python setup_env.py

# 跑全部（每轮会自动重建测试环境，保证结果可重复）
python run.py

# 只跑某个模块
python run.py --module booking
python run.py --module auth,queue

# 按编号前缀过滤
python run.py --id BOOK-0

# 沿用当前数据、不重建（调试用；AUTH 锁定类用例可能因 15 分钟锁定而失败）
python run.py --keep
```

## 3. 脚本会动哪些数据

`setup_env.py` 每次运行会**先删后建**，只碰本套件自己的数据，不动现有业务数据：

| 类型 | 命名规则 |
|---|---|
| 账号 | `t_admin`、`t_live`、`t_viewer`、`t_farmer1..3`，探针 `t_must_*`、`t_pwd_*`、`t_lock_*`、`t_disabled` |
| 农户 | `NFTEST01..03` |
| 场地 | `C900`（08:00–22:00） |
| 设备 | `ZBT-C900-01..03` |

所有测试账号统一密码 **`Test@1234`**（可用环境变量改）。

> 每轮执行都会清理上一轮的预约、排队、调整、通知、故障记录，所以可以反复跑。

## 4. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `FARM_API` | `http://127.0.0.1:8080` | 后端地址 |
| `FARM_TEST_PASSWORD` | `Test@1234` | 测试账号密码 |
| `MYSQL_EXE` | 见上 | mysql 客户端路径 |
| `FARM_CHECK_DB` | `1` | 设 0 时跳过依赖查库的用例 |
| `FARM_DB_HOST/PORT/USER/PASSWORD/NAME` | 本机 farm_live | 数据库连接 |

示例：

```powershell
$env:FARM_API = "http://192.168.1.10:8080"
$env:FARM_TEST_PASSWORD = "Qa@2026test"
python run.py
```

## 6. 结果与报告

- 控制台：每条一行 `[PASS]/[FAIL]/[SKIP]`
- 报告：`testing/reports/report-<时间戳>.md`（含分模块汇总、明细、失败原因）
- 退出码：全通过为 0，有失败为 1（可直接接 CI）

## 7. 已知限制

1. **AI 用例**：后端未配 `AI_CHAT_API_KEY` 时，`AI-04` 会跳过（接口返回 400 `AI_CHAT_NOT_CONFIGURED`），其余 AI 用例仍可跑。
2. **模块顺序**：`notify`、`stats` 依赖前面模块产生的数据，建议整体运行；只跑单模块时，这两块可能出现前置数据不足。
3. **`--keep` 模式**：登录失败 3 次会锁定 15 分钟（内存态），连续执行 `AUTH-03` 会失败；正常模式每轮换新探针账号，不受影响。
4. **时间类用例**：不修改系统时间，靠构造不同日期的数据覆盖 2 小时 / 24 小时 / 30 天边界。
5. **未覆盖**：并发压测（需 JMeter）、真实短信网关、浏览器交互（UI 只做可用性冒烟）。
