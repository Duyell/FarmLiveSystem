# 开发规范

| 项 | 内容 |
|---|---|
| 文档编号 | 开发-00 |
| 版本 | 1.0 |
| 适用 | 后端、前端、测试 |

---

## 1. 分支

- `main`：可运行、可构建；
- `feature/模块名`：一个功能一个分支；
- 合并前先拉最新 `main`，解决冲突后再提交；
- 团队协作后不直接推 `main`，通过合并请求进入。

---

## 2. 提交

提交说明不能只写一行标题，必须写清三件事：

1. 改了什么；
2. 为什么改；
3. 怎么验证。

模板见 `commit-template.txt`：

```text
<类型>: <一句话说明>

改了什么：
为什么改：
怎么验证：
关联任务：
```

类型只用：

| 类型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修缺陷 |
| `docs` | 改文档 |
| `test` | 加测试 |
| `refactor` | 重构，不改行为 |
| `chore` | 构建、依赖、配置 |

示例：

```text
feat: 增加区域查询接口

改了什么：新增 GET /api/regions，按 parentCode 返回省、市、县。
为什么改：农户和场地要按标准区域编码保存，不能继续用自由文本。
怎么验证：分别调用省级、市级、县级请求，确认逐级返回；农户保存后能按 countyCode 查询。
关联任务：基础-02
```

```text
fix: 修复场地删除约束

改了什么：删除场地前检查是否还有设备，有设备时返回 409。
为什么改：原来直接删场地会留下无归属设备，设备列表查不到所属场地。
怎么验证：创建场地和设备，删除场地被拒绝；删设备后再删场地成功。
关联任务：基础-08
```

提交前检查：

- 提交说明包含“改了什么、为什么改、怎么验证”三行，缺一不可；
- 代码能构建；
- 没有密钥、真实手机号、生产数据；
- 数据库变更带 SQL；
- 接口变更同步文档。

> 只有标题、没有说明的提交视为不合格，不能合并到 `main`。

---

## 3. 后端

- Java 17，Spring Boot 3；
- 接口统一返回 `code`、`message`、`data`；
- 参数校验写在接口入口；
- 业务异常用统一异常处理，不把堆栈返回给前端；
- 数据库访问集中在数据访问层，不把 SQL 散落在控制器；
- 时间统一用 `Asia/Shanghai`；
- 关键业务规则写注释，注释解释“为什么”，不写废话。

---

## 4. 前端

- Vue 3 + TypeScript + Element Plus；
- 页面、接口、类型分开；
- 接口错误统一提示；
- 登录失效统一回登录页；
- 手机网页宽度 375–428 像素不横向滚动；
- 不在前端写死区域、角色等基础数据。

---

## 5. 数据库

- 新环境执行 `init.sql`；
- 已有环境执行 `deploy/sql/` 下的增量脚本；
- 表名、字段名用小写下划线；
- 关键唯一性用唯一约束兜底；
- 不存身份证号、家庭住址；
- 手机号展示默认脱敏；
- 每次结构变更写清楚影响范围。

---

## 6. 联调

- 后端先调通接口，前端再接；
- 接口地址、字段、错误码以接口文档为准；
- 外部短信、大模型不可用时，用模拟或降级，不阻塞主流程；
- 联调问题记录在任务或缺陷清单里，不口头解决。

---

## 7. 评审

- 数据库、接口、关键业务规则由项目负责人评审；
- 代码由另一名开发抽查；
- 测试按验收标准验证，不只看页面能不能点；
- 评审发现的问题要关闭后再合并。

---

## 8. 禁止

- 提交真实密钥、证书、生产数据；
- 直接把调试代码、临时开关、测试账号带到主分支；
- 跳过数据库脚本手工改表；
- 接口改了不更新文档；
- 用“大概”“应该”描述验收结果。
