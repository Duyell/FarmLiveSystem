# 开发规范

| 项 | 内容 |
|---|---|
| 文档编号 | 开发-00 |
| 版本 | 1.0 |
| 适用 | 后端、前端、测试 |

---

## 1. 分支

- `main`：可运行、可构建；
- `feature/模块名`：一个功能一个分支；
- 合并前先拉最新 `main`，解决冲突后再提交；
- 团队协作后不直接推 `main`，通过合并请求进入。

---

## 2. 提交

提交说明写清楚改了什么、为什么改、怎么验证：

```text
feat: 增加区域查询接口
fix: 修复场地删除约束
docs: 补充接口文档
test: 增加预约并发测试
```

提交前检查：

- 代码能构建；
- 没有密钥、真实手机号、生产数据；
- 数据库变更带 SQL；
- 接口变更同步文档。

---

## 3. 后端

- Java 17，Spring Boot 3；
- 接口统一返回 `code`、`message`、`data`；
- 参数校验写在接口入口；
- 业务异常用统一异常处理，不把堆栈返回给前端；
- 数据库访问集中在数据访问层，不把 SQL 散落在控制器；
- 时间统一用 `Asia/Shanghai`；
- 关键业务规则写注释，注释解释“为什么”，不写废话。

---

## 4. 前端

- Vue 3 + TypeScript + Element Plus；
- 页面、接口、类型分开；
- 接口错误统一提示；
- 登录失效统一回登录页；
- 手机网页宽度 375–428 像素不横向滚动；
- 不在前端写死区域、角色等基础数据。

---

## 5. 数据库

- 新环境执行 `init.sql`；
- 已有环境执行 `deploy/sql/` 下的增量脚本；
- 表名、字段名用小写下划线；
- 关键唯一性用唯一约束兜底；
- 不存身份证号、家庭住址；
- 手机号展示默认脱敏；
- 每次结构变更写清楚影响范围。

---

## 6. 联调

- 后端先调通接口，前端再接；
- 接口地址、字段、错误码以接口文档为准；
- 外部短信、大模型不可用时，用模拟或降级，不阻塞主流程；
- 联调问题记录在任务或缺陷清单里，不口头解决。

---

## 7. 评审

- 数据库、接口、关键业务规则由项目负责人评审；
- 代码由另一名开发抽查；
- 测试按验收标准验证，不只看页面能不能点；
- 评审发现的问题要关闭后再合并。

---

## 8. 禁止

- 提交真实密钥、证书、生产数据；
- 直接把调试代码、临时开关、测试账号带到主分支；
- 跳过数据库脚本手工改表；
- 接口改了不更新文档；
- 用“大概”“应该”描述验收结果。
