# 助农直播管理系统 · 编码与注释规范

| 项 | 内容 |
|---|---|
| 文档编号 | C3-02 |
| 版本 | v1.0 |
| 编制/审核 | P2 / P3 / P4 |
| 适用范围 | Java、TypeScript/Vue、SQL、Python（AI 服务） |
| 强制指标 | 源码注释率 ≥50%；核心单测覆盖率 ≥70%；静态扫描 Blocker/Critical = 0 |

---

## 1. 总则

1. **可读优先**：代码给人看，顺带给机器执行；命名即注释。
2. **简单优先**：能用 3 行写清，不引入设计模式；拒绝过度抽象。
3. **显式优先**：不吞异常、不返回魔法值、不隐式转换。
4. **边界清晰**：Controller 不写业务，Service 不拼 SQL，Mapper 不判权限。
5. **安全默认**：默认拒绝、默认脱敏、默认校验、默认记录 traceId。
6. **注释解释"为什么"**，不复述"是什么"；但公共 API 必须说明"做什么、参数、返回、异常"。

## 2. Java 规范

### 2.1 工程结构

```text
com.farm.live
├─ common/            # 通用：响应、异常、工具、常量、拦截器
├─ auth/              # 登录、RBAC、审计
│  ├─ controller/
│  ├─ application/
│  ├─ domain/
│  └─ infrastructure/
├─ base/              # 农户、资质、设备、场地
├─ booking/
├─ queue/
├─ notify/
├─ stats/
├─ kb/
└─ integration/
```

- 每个模块四层：`controller → application → domain → infrastructure`。
- 跨模块调用 `application` 接口；禁止直接注入对方 Mapper。
- `common` 不依赖任何业务模块。

### 2.2 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类 | UpperCamel | `BookingApplicationService` |
| 方法/变量 | lowerCamel | `calculateQueuePosition` |
| 常量 | UPPER_SNAKE | `MAX_BOOKING_HOURS` |
| DTO | `XxxReq` / `XxxResp` | `BookingCreateReq` |
| 实体 | `XxxEntity` | `BookingEntity` |
| 枚举 | `XxxStatus` | `BookingStatus` |
| 布尔 | `is/has/can` | `isCertified` |

禁止：拼音命名、`data1`、`temp`、`obj`、单字母（循环除外）、缩写歧义（`bk`）。

### 2.3 分层职责

| 层 | 做 | 不做 |
|---|---|---|
| Controller | 参数校验、鉴权注解、调 Application、返回统一响应 | 业务判断、事务、SQL |
| Application | 用例编排、事务边界、权限与数据范围、事件发布 | 直接拼 SQL、HTTP 细节 |
| Domain | 实体、值对象、领域规则（状态机、冲突判定） | Spring 注解、数据库访问 |
| Infrastructure | Mapper、Redis、文件、短信、LLM 适配 | 业务规则 |

### 2.4 异常与响应

- 业务异常统一 `BizException(code, message, httpStatus)`；全局 `@RestControllerAdvice` 转换。
- 禁止 `catch (Exception e) {}` 空吞；必须记录 traceId 或转换。
- 禁止把 `Exception.message` 直接返回给前端（可能含 SQL/路径）。
- 校验异常返回字段级 `errors`。
- 不返回 `null` 集合；用空列表。
- `Optional` 仅用于返回值，不用于字段/参数。

### 2.5 事务与并发

- 事务只包 DB 操作；短信/LLM/文件在事务外（Outbox）。
- `@Transactional(rollbackFor = Exception.class)`；只读查询 `readOnly = true`。
- 禁止大事务（>1 秒）；批量操作分批提交。
- 乐观锁：`UPDATE ... WHERE id=? AND version=?`，影响行数 0 抛 409。
- 唯一约束冲突必须捕获并转业务错误，不能 500。
- 禁止 `synchronized` 做跨实例互斥；用 DB/Redis。

### 2.6 日志

```java
log.info("booking approved, bookingId={}, operatorId={}, traceId={}",
         bookingId, operatorId, MDC.get("traceId"));
```

- 使用 SLF4J 占位符，禁止字符串拼接。
- 不打印密码、token、完整手机号、资质内容。
- 异常打印堆栈仅 `log.error("...", e)`，不重复打印。
- 关键节点：请求入口/出口、状态变更、外部调用、重试、降级。
- 日志级别：ERROR 需告警、WARN 可恢复异常、INFO 业务关键、DEBUG 调试（生产关闭）。

### 2.7 配置

- 业务参数走 `sys_config`；环境配置走 `application-{profile}.yml` + 环境变量。
- 禁止硬编码 URL、密钥、阈值、开关。
- 配置项命名：`模块.语义.单位`，如 `queue.candidate.ttl.hours`。
- 新增配置必须有默认值 + 说明 + 是否可热更新。

### 2.8 SQL / MyBatis

- 只用 `#{}`；`${}` 仅白名单排序字段，且用枚举校验。
- 禁止 `SELECT *`；显式列。
- 分页必须带 `ORDER BY` 唯一键，避免重复/漏行。
- 批量插入 ≤500 条；`foreach` 注意 SQL 长度。
- 逻辑删除条件统一封装，避免漏加。
- 复杂 SQL 写注释说明业务含义与索引。

## 3. TypeScript / Vue 规范

### 3.1 基本

- 全部 `<script setup lang="ts">`；禁止 Options API（除第三方示例）。
- `strict: true`；禁止 `any`（必要时 `unknown` + 收窄）。
- 组件名 PascalCase，文件名与组件一致；页面放 `views/`，通用组件放 `components/`。
- 组合式函数 `useXxx.ts`；状态 `stores/xxx.ts`。
- API 调用统一走 `packages/api-client`，禁止组件内散落 `axios`。

### 3.2 组件

```vue
<script setup lang="ts">
interface Props {
  bookingId: string
  status: BookingStatus
}
const props = defineProps<Props>()
const emit = defineEmits<{ refresh: [id: string] }>()
</script>
```

- Props/Emits 必须类型化；禁止 `defineProps(['a'])`。
- 一个组件 ≤300 行；超过拆分。
- 容器组件管数据，展示组件管渲染。
- `v-for` 必须 `:key`（业务 ID，不用 index）。
- 禁止 `v-html`（除知识库富文本，须白名单过滤）。

### 3.3 状态与请求

- Pinia 按模块；不把页面局部状态放全局。
- 请求统一拦截：token、traceId、错误码、401 刷新、403 提示。
- 加载/空/错误/无权限四态必须处理。
- 表单校验：前端即时 + 后端为准；错误定位到字段。
- 防抖/节流用于搜索、提交；提交按钮 loading 防重复。

### 3.4 样式

- 使用设计令牌（CSS 变量），禁止散落十六进制色值。
- `<style scoped>`；全局样式仅 `styles/` 下。
- 类名 BEM 或语义化：`.booking-card__title--disabled`。
- 禁止 `!important`（除覆盖第三方库，需注释）。
- H5 用 `px` + postcss 转 vw；安全区适配。

### 3.5 可访问性

- 图标按钮加 `aria-label`；表单 `label` 关联。
- 键盘可操作；焦点可见。
- 状态不只靠颜色。

## 4. Python（AI 服务）规范

- PEP 8；`ruff` + `black`；类型注解 + `mypy`（可选）。
- 分层：`api/`（路由）、`rag/`（检索/生成）、`core/`（配置/日志）、`models/`（schema）。
- 外部调用超时/重试/熔断；异常转统一错误。
- Prompt 模板放 `prompts/` 并版本化；禁止硬编码在路由。
- 日志脱敏；不打印完整问题与答案（截断 + 掩码）。

## 5. 注释规范（重点：注释率 ≥50%）

### 5.1 必须注释

| 位置 | 要求 |
|---|---|
| 类/接口 | 职责、作者、since |
| public 方法 | 做什么、参数、返回、异常、副作用 |
| 复杂算法 | 冲突判定、顺位计算、TTL、冷却 |
| 状态机 | 允许的流转与拒绝原因 |
| 配置项 | 含义、单位、默认值、影响 |
| SQL | 业务含义、索引使用 |
| 前端组件 | 用途、props/emits、状态 |
| 特殊 hack | 为什么必须这样，何时可移除 |

### 5.2 禁止

- 复述代码：`i++; // i 加 1`
- 过期注释（改了代码不改注释）
- 注释掉的代码（用 Git 历史）
- `// TODO` 无负责人/Issue
- 用注释"美化"注释率（无意义填充）——评审发现按违规处理

### 5.3 示例

```java
/**
 * 计算农户在指定资源队列中的顺位。
 *
 * <p>排序键为 created_at, id，仅统计 WAITING/CANDIDATE；
 * 与 Redis ZSET 的顺位可能短暂不一致，以 DB 为准（见 R1-02 §5.2）。
 *
 * @param deviceId 设备 ID
 * @param slotStart 时段起点（UTC）
 * @param createdAt 我的入队时间
 * @param id 我的排队 ID
 * @return 从 1 开始的顺位；无记录返回 1
 */
public int calculatePosition(long deviceId, Instant slotStart, Instant createdAt, long id) {
    // 同一毫秒入队时用 id 决胜，避免顺位并列
    return queueMapper.countBefore(deviceId, slotStart, createdAt, id) + 1;
}
```

```ts
/**
 * 预约状态标签。
 * 颜色不是唯一信息载体：必须同时渲染文案，满足可访问性要求（D2-05 §5.1）。
 */
const statusMeta: Record<BookingStatus, { label: string; type: 'success' | 'warning' | 'danger' | 'info' }> = {
  PENDING_REVIEW: { label: '待审核', type: 'warning' },
  APPROVED: { label: '已通过', type: 'success' },
  // ...
}
```

### 5.4 注释率度量（唯一口径）

**公式**：

```
注释率 = 注释行数 / (有效代码行数 + 注释行数) × 100%
```

- 使用 `cloc --by-file --json` 的 `comment` 与 `code` 字段。
- 统计范围：`backend/src/main/java`、`frontend/apps/*/src`、`frontend/packages/*/src`、`ai-service/app`。
- 排除：`target/`、`node_modules/`、`dist/`、生成代码（`generated/`、`*.g.dart`）、第三方、`.d.ts`、测试数据。
- 测试代码不计入分子分母（另行考核覆盖率）。
- 目标 ≥50%；低于 45% 阻断合并，45–50% 警告。

**脚本示例**（CI 执行）：

```bash
cloc --json --quiet \
  --exclude-dir=target,node_modules,dist,generated \
  backend/src/main/java frontend/apps frontend/packages ai-service/app > cloc.json
# 解析 comment/code，计算比例；<0.45 exit 1
```

> **反作弊**：评审抽查注释是否解释"为什么"；发现无意义填充，按 P1 缺陷处理并重算。

## 6. 测试代码规范

- 命名：`should<Expected>_when<Condition>` 或 `[REQ-XXX-NN] Given...When...Then`。
- 一个测试一个断言主题；避免"大杂烩"。
- 必须断言具体值/状态/异常码，禁止只断言"不抛异常"。
- 禁止条件豁免式断言（`if (x) assert...`）导致假绿。
- 使用 Testcontainers 做真实 DB 集成测试；Mock 仅外部依赖。
- 测试数据工厂统一，禁止复制粘贴大段 JSON。
- 核心用例必须能在 CI 重复稳定运行（无随机、无时间依赖）。

## 7. 代码坏味道与禁止清单

| 禁止 | 原因 | 替代 |
|---|---|---|
| Controller 写业务 | 难测、难复用 | Application 层 |
| `SELECT *` | 性能/耦合 | 显式列 |
| 字符串拼 SQL | 注入 | `#{}` |
| 空 catch | 掩盖故障 | 记录/转换 |
| `System.out` | 无级别/无 traceId | SLF4J |
| 魔法值 | 难维护 | 常量/枚举/配置 |
| 深层嵌套 >3 层 | 难读 | 早返回/抽取 |
| 一个方法 >80 行 | 难测 | 拆分 |
| 循环内远程调用 | N+1/超时 | 批量/异步 |
| 前端 `any` | 类型失效 | 明确类型 |
| 硬编码域名/密钥 | 安全/环境 | 配置 |
| 注释掉的代码 | 噪声 | 删除，靠 Git |
| `TODO` 无主 | 技术债 | Issue + 负责人 |
