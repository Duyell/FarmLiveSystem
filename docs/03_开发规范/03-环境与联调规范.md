## 2. 本地启动

### 2.1 前置

- JDK 17、Maven 3.9（用 `mvnw`）
- Node 20、pnpm 9
- Python 3.11
- Docker Desktop / Docker Engine + Compose v2
- Git 2.4x

### 2.2 一键启动中间件

```bash
docker compose -f deploy/docker-compose.dev.yml up -d
docker compose -f deploy/docker-compose.dev.yml ps
```

包含：mysql（初始化 `db/migration` + `seed/demo.sql`）、redis、minio（自动建桶）、qdrant。

### 2.3 启动应用

```bash
# 后端
cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

# 管理端
cd frontend
pnpm install
pnpm --filter admin dev

# 农户端
pnpm --filter h5 dev

# AI
cd ai-service
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 2.4 健康检查

| 服务 | 检查 |
|---|---|
| app | `GET http://localhost:8080/actuator/health` → `UP` |
| ai | `GET http://localhost:8000/health` → `{"status":"ok"}` |
| MySQL | `mysqladmin ping` |
| Redis | `redis-cli ping` → `PONG` |
| MinIO | 控制台登录，桶 `farm-qualification` 存在 |
| Qdrant | `GET http://localhost:6333/collections` |

## 3. 配置管理

### 3.1 Profile

| Profile | 用途 | 特点 |
|---|---|---|
| `dev` | 本地 | SQL 日志、Mock 短信/LLM、宽松 CORS |
| `test` | 集成 | Mock 外部、固定时钟可选 |
| `staging` | 预发 | 沙箱、接近生产 |
| `prod` | 生产 | 关闭调试、严格 CORS、真实依赖 |

### 3.2 配置分层

```text
application.yml            # 公共默认
application-dev.yml        # 开发覆盖
application-prod.yml       # 生产覆盖（不含密钥）
环境变量                    # 密钥/连接串/开关
```

### 3.3 关键环境变量

```bash
# 数据库
DB_HOST=mysql
DB_PORT=3306
DB_NAME=farm_live
DB_USER=farm_app
DB_PASSWORD=***

# Redis
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=***

# MinIO
MINIO_ENDPOINT=http://minio:9000
MINIO_ACCESS_KEY=***
MINIO_SECRET_KEY=***
MINIO_BUCKET=farm-qualification

# 安全
JWT_SECRET=***            # ≥32 字节
DATA_KEY=***              # base64 32 字节
HMAC_KEY=***              # ≥32 字节

# 外部
SMS_PROVIDER=mock         # mock/aliyun
SMS_ACCESS_KEY=***
LLM_PROVIDER=deepseek
LLM_API_KEY=***
LLM_BASE_URL=https://api.deepseek.com
QDRANT_URL=http://qdrant:6333

# 开关
AI_LLM_ENABLED=true
AI_VECTOR_ENABLED=true
INTEGRATION_FARM_SYNC_ENABLED=false
```

> `.env.example` 入库；`.env` 不入库；生产用密钥管理，不落盘明文。

### 3.4 配置校验

启动时校验：必填项缺失/长度不足 → 生产拒绝启动；开发打印警告。配置项变更走 `sys_config` + 二次验证 + 审计。

## 5. Mock 与外部依赖

### 5.1 短信

- `SMS_PROVIDER=mock`：日志打印 + 写入 `notification`，管理端"模拟短信"页可查。
- 沙箱：阿里云测试模板，仅白名单号码。
- 生产：真实签名/模板，失败自动重试。

### 5.2 LLM

- `LLM_PROVIDER=mock`：返回固定 FAQ 答案 + 引用，用于无 Key 联调。
- 真实：DeepSeek Key，限额；失败切备。

### 5.3 支付/物流

无（范围外）。

### 5.4 Mock 原则

- Mock 必须返回与真实契约一致的 HTTP 状态码与错误码。
- Mock 不得绕过权限/校验（用真实拦截器）。
- Mock 数据放 `deploy/mock/`，随仓库版本化。

## 6. 联调流程

### 6.1 准入

- [ ] OpenAPI 已更新并导入 Apifox
- [ ] 接口在 test 环境可访问
- [ ] 示例请求/响应齐全（含错误码）
- [ ] 鉴权方式确认（token/角色/二次验证）
- [ ] 测试数据就绪

### 6.2 步骤

```text
1. 后端自测（Postman/Apifox）：200 + 400 + 403 + 409
2. 前端接 Mock → 页面四态
3. 切 test 环境真实接口
4. 双端联调：主流程 → 异常 → 边界
5. 记录问题（接口/字段/错误码/性能）
6. 回归 + 更新契约
```

### 6.3 联调完成定义（DoD）

- [ ] 主流程 + 至少 3 条异常分支通过
- [ ] 字段命名/类型/时间格式一致
- [ ] 错误码前端有对应文案与处理
- [ ] 分页/排序/筛选行为一致
- [ ] 权限与数据范围验证
- [ ] 响应 P95 达标
- [ ] 日志有 traceId，可串联
- [ ] 契约文档已更新

### 6.4 问题升级

| 问题 | 处理 |
|---|---|
| 接口字段不一致 | 以 OpenAPI 为准；改动方更新文档并通知 |
| 后端未就绪 | 前端继续 Mock；每日站会通报 |
| 环境不可用 | P5 30 分钟内响应；超过 2 小时升级 P2 |
| 性能不达标 | 记录 P95/慢 SQL，P2 排期优化 |

## 7. 跨域、鉴权与常见问题

### 7.1 CORS

- dev：允许 `http://localhost:5173/5174`。
- test/staging/prod：仅允许配置的域名；禁止 `*`。
- 预检缓存 1 小时。

### 7.2 常见错误

| 现象 | 排查 |
|---|---|
| 401 | token 过期/未带 header/黑名单 |
| 403 | 角色/数据范围/二次验证缺失 |
| 409 | 资源冲突/状态机/幂等重复（看 `code`） |
| CORS | Origin 不在白名单/预检失败 |
| 上传失败 | 大小/类型/桶权限/签名过期 |
| SSE 无输出 | Nginx 缓冲未关闭（`proxy_buffering off`） |
| 时间差 8 小时 | 时区未按 Asia/Shanghai 转换 |
| 中文乱码 | 连接未 `utf8mb4` |

### 7.3 SSE 配置

```nginx
location /api/v1/ai/ {
    proxy_pass http://app:8080;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;
    proxy_read_timeout 120s;
}
```

## 8. 数据与时间

- 数据库存 UTC；展示按 `Asia/Shanghai`；API 带 `+08:00`。
- 服务器 NTP 同步；容器时区 `TZ=Asia/Shanghai`。
- 测试固定时钟：集成测试可注入 `Clock`，避免"当前时间"导致用例不稳定。
- 跨天/12h/72h 边界用例必须用固定时钟。

## 9. 环境纪律

1. 禁止在 test/staging 使用真实农户数据；必须脱敏。
2. 禁止本地直连生产库；生产操作走跳板/审计。
3. 禁止在共享环境随意改配置；改前在群里报备。
4. 每日 18:00 后冻结 test 环境（除 P0 修复），保证回归稳定。
5. 环境故障记录到运维台账，24 小时内复盘。
