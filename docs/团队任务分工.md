## 1. 适用范围

本文档只覆盖当前项目的交付范围和收尾工作，不把新功能继续塞进本次开发。

- 当前已完成：登录权限、基础数据、区域、资质、预约、调整、排队候补、通知、销售、统计、工作台、操作日志、设备故障闭环；

## 3. 项目经理

### 3.1 负责范围

项目经理对“做什么、什么时候交、是否达到验收标准”负责，不代替开发写业务代码。

| 任务 | 具体内容 | 交付物 | 完成标准 |
|---|---|---|---|
| 范围冻结 | 确认本次交付包含哪些功能，未完成项列入后续迭代 | 范围清单、变更记录 | 团队对“本次做什么”无歧义 |
| 计划管理 | 拆分收尾任务，明确负责人和时间点 | 收尾计划、任务看板 | 每项任务有负责人和截止时间 |
| 风险管理 | 跟踪并发测试、真机适配、部署备份等风险 | 风险清单 | 风险有应对人和处理状态 |
| 需求澄清 | 对开发、测试提出的需求歧义做最终解释 | 需求澄清记录 | 开发和测试理解一致 |
| 验收组织 | 组织功能演示、缺陷复盘、验收确认 | 验收记录、问题清单 | 验收项逐条有结论 |
| 跨角色协调 | 处理前后端接口、测试环境、设计变更冲突 | 会议结论/任务单 | 冲突有明确结论和责任人 |
| 交付管理 | 汇总代码、数据库脚本、文档、演示账号 | 交付包清单 | 代码、数据、文档版本一致 |
| 变更控制 | 开发冻结后新增需求统一评估，不直接插队 | 变更申请/结论 | 变更不影响本次验收 |

### 3.2 当前必须完成

1. 确认本次验收的功能清单和演示顺序；
2. 确认测试与运维拿到可用的测试环境和演示数据；
3. 组织一次完整主流程演示：农户预约 → 审核 → 排队/候补 → 完成 → 销售 → 统计 → 通知；
4. 确认并发/边界测试、手机真机回归、部署备份是否有结论；
5. 汇总最终交付包和遗留问题，不以“功能能做”代替“验收通过”。

### 3.3 项目经理不负责

- 不直接改后端业务逻辑；
- 不直接改前端页面；
- 不替代测试出具测试结论；
- 不绕过 UI/UX 直接定视觉细节。

## 4. 后端开发（兼技术负责人）

### 4.1 负责范围

后端开发同时承担技术负责人职责：架构、数据库、API、核心业务、技术风险和代码质量。

| 任务 | 具体内容 | 交付物 | 完成标准 |
|---|---|---|---|
| 技术架构 | 维护 Spring Boot + Spring JDBC + MySQL 架构，控制技术风险 | 架构说明、技术决策记录 | 新功能不破坏现有架构 |
| 数据库设计 | 维护 19 张表、索引、外键和迁移脚本 | `init.sql`、`deploy/sql/*.sql` | 新环境可一次建库，旧库可增量迁移 |
| 区域字典 | 维护全国省/市/区县（含港澳台）数据和 `/api/regions` | 区域数据、接口 | 3,947 条区域可查询，寿县等旧编码不断 |
| 登录权限 | 登录、验证码、失败锁定、改密、角色拦截 | 认证接口、权限规则 | 四类角色只能访问授权接口 |
| 基础数据 | 农户、场地、设备组合、资质、区域 | CRUD 接口 | 新增/修改/删除/查询可用，约束生效 |
| 预约 | 提交、冲突校验、审核、取消、完成 | 预约接口 | 同场地同时段只成功一场 |
| 调整 | 调整申请、审批、资源切换 | 调整接口 | 通过后新资源生效，原资源释放 |
| 排队候补 | 排队、顺位、候补确认、超时、关闭 | 排队接口 | 排队绑定 `queued` 预约，确认复用该预约 |
| 通知 | 审核、排队、候补、调整、设备故障、恢复 | 通知服务、模板 | 业务动作触发站内/短信记录 |
| 销售统计 | 销售录入、四项指标、趋势、CSV、农户统计 | 统计接口 | 数据口径一致，数据统计员看不到明细 |
| 设备故障 | 报修、维修完成、自动取消受影响预约、释放资源 | 故障接口、故障记录 | 故障组合停用，受影响预约取消并通知 |
| 操作日志 | 关键业务写审计日志 | 日志接口 | 关键操作可追溯 |
| 接口文档 | 维护接口路径、参数、权限、错误码 | 接口文档 | 与代码一致 |
| 技术支持 | 给测试提供日志、SQL、环境说明；给运维提供部署参数 | 技术支持记录 | 测试/运维问题能定位 |
