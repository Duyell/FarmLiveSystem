## 1. 通用约定

### 1.1 请求格式

- 请求体：JSON，`Content-Type: application/json`
- 时间：`yyyy-MM-dd HH:mm:ss`
- 日期：`yyyy-MM-dd`
- 时间时段：`HH:mm`
- 分页：`page` 从 1 开始，`size` 默认 10

### 1.2 响应格式

成功：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {}
}
```

失败：

```json
{
  "code": "BAD_REQUEST",
  "message": "用户名已存在",
  "data": null
}
```

### 1.3 状态码

| HTTP | code | 含义 |
|---|---|---|
| 200 | OK | 成功 |
| 400 | BAD_REQUEST | 参数错误、业务校验失败 |
| 401 | UNAUTHORIZED | 未登录或令牌失效 |
| 403 | FORBIDDEN | 无权限 |
| 404 | NOT_FOUND | 数据不存在 |
| 409 | CONFLICT | 唯一约束冲突、状态冲突 |
| 500 | SERVER_ERROR | 服务器异常 |

### 1.4 分页响应

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "size": 10
  }
}
```

## 2. 登录与当前用户

### 2.1 健康检查

`GET /api/health`，不需要登录。

响应：

```json
{"code":"OK","message":"成功","data":{"status":"UP"}}
```

### 2.2 登录

`POST /api/auth/login`

请求：

```json
{
  "username": "admin",
  "password": "Admin@123"
}
```

- `roleCode` 为可选兼容字段，登录页不传；后端按账号实际角色返回，前端登录后按角色加载页面；
- 传入时后端校验与账号实际角色一致，不一致返回 403“角色不匹配”。

响应：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "token": "8f3c...",
    "user": {
      "id": 1,
      "username": "admin",
      "displayName": "系统管理员",
      "roleCode": "system_admin",
      "roleName": "系统管理员",
      "mustChangePassword": true
    }
  }
}
```

失败：401 `UNAUTHORIZED`，提示“用户名或密码错误”。

### 2.3 当前用户

`GET /api/auth/me`

响应：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "id": 1,
    "username": "admin",
    "displayName": "系统管理员",
    "roleCode": "system_admin",
    "roleName": "系统管理员",
    "mustChangePassword": false
  }
}
```

### 2.4 修改密码

`POST /api/auth/change-password`

请求：

```json
{
  "oldPassword": "Admin@123",
  "newPassword": "NewPass@123"
}
```

规则：

- 新密码至少 8 位，包含字母和数字；
- 修改成功后 `mustChangePassword` 变为 0；
- 旧密码错误返回 400。

### 2.5 退出登录

`POST /api/auth/logout`

- 服务端使当前令牌失效；
- 前端清除本地令牌。

权限：全部登录用户。

`GET /api/regions?parentCode=340000`

- 传省级编码返回市；
- 传市级编码返回县；
- 只返回 `enabled = 1` 的区域；
- 按编码排序，保证逐级返回顺序稳定。

响应：

```json
{

  "message": "成功",
  "data": [

  ]
```

已完成的改造：

- 场地新增/修改接口增加 `countyCode`（同上）；

- 前端农户、场地页面已改成省、市、县三级选择；
- `county` 文本保留为显示快照，`county_code` 作为筛选和统计依据。

### 3.17 可用资源查询

`GET /api/resources/available?date=2026-11-01&startTime=10:00&endTime=12:00&countyCode=340422`

权限：全部登录用户。已实现。

- `date`、`startTime`、`endTime` 可选：传入时排除该时段已有有效预约（待审核 / 已通过）的场地和设备；
- 没有可用设备的场地不返回。

响应：

```json
{
  "code": "OK",
  "message": "成功",
  "data": [
    {
      "venueId": 1,
      "venueNo": "C001",
      "venueName": "一号直播间",
      "countyCode": "340422",
      "devices": [
        {"deviceId": 1, "deviceNo": "ZB-C001-01", "name": "主摄像机"}
      ]
    }
  ]
}
```

规则：

- 先查场地是否开放、未被占用；
- 再查场地内状态为 `available` 的设备；
- 没有可用设备的场地不返回；
- 场地、设备都不在前端写死。

## 5. 预约接口

### 5.1 接口清单

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| POST | `/api/farmer/bookings` | 农户 | 提交预约 |
| GET | `/api/farmer/bookings` | 农户 | 我的预约列表 |
| GET | `/api/farmer/bookings/{id}` | 农户 | 预约详情 |
| POST | `/api/farmer/bookings/{id}/cancel` | 农户 | 取消预约 |
| POST | `/api/farmer/bookings/{id}/adjustments` | 农户 | 提交调整申请 |
| GET | `/api/farmer/adjustments` | 农户 | 我的调整申请 |
| POST | `/api/farmer/adjustments/{id}/withdraw` | 农户 | 撤回调整申请 |
| GET | `/api/live/bookings` | 直播管理员 | 预约列表 |
| POST | `/api/live/bookings/{id}/review` | 直播管理员 | 审核通过或驳回 |
| POST | `/api/live/bookings/{id}/complete` | 直播管理员 | 场次结束标记完成/未到场 |
| POST | `/api/live/bookings/{id}/cancel` | 直播管理员 | 异常强制取消（待开发） |
| GET | `/api/live/adjustments` | 直播管理员 | 调整申请列表 |
| POST | `/api/live/adjustments/{id}/review` | 直播管理员 | 审批调整申请 |

### 5.2 提交预约

请求：

```json
{
  "venueId": 1,
  "deviceId": 1,
  "startTime": "2026-11-01 10:00:00",
  "endTime": "2026-11-01 12:00:00",
  "topic": "寿县草莓直播",
  "products": [
    {"productName": "草莓", "spec": "500g/盒", "quantity": 100, "unit": "盒"}
  ]
}
```

校验：

- 场地存在且可用；
- 设备存在、可用，并且属于该场地；
- 时段为整点、1–4 小时、不跨天；
- 开始时间至少晚于当前 2 小时，最多提前 30 天；
- 同一农户同一时段只能有一条有效预约；
- 冲突时返回 409，并返回冲突的场地或设备。

响应：预约对象，状态 `pending_review`。

### 5.3 审核

请求：

```json
{
  "result": "approve",
  "comment": "",
  "recommendedTime": null
}
```

- `result`：`approve` 或 `reject`；
- 驳回时 `comment` 至少 5 个字，`recommendedTime` 必填且可预约；
- 通过时写入资源占用，状态变为 `approved`；
- 重复审核返回 409。

### 5.4 场次完成

`POST /api/live/bookings/{id}/complete`

```json
{"status": "completed"}
```

- 只有 `approved` 且已过结束时间的预约可以标记；
- `status` 只能是 `completed` 或 `no_show`；
- 完成后才能录入销售记录。

### 5.5 调整申请

请求：

```json
{
  "newVenueId": 2,
  "newDeviceId": 3,
  "newStartTime": "2026-11-02 14:00:00",
  "newEndTime": "2026-11-02 16:00:00",
  "reason": "农户临时改期"
}
```

- 开播前 24 小时外才能申请；
- 同一预约同时只能有一条待审批调整；
- 审批期间原预约保持 `approved`；
- 通过时先锁新资源，再释放旧资源；新资源冲突则审批失败，原预约不变。

直播管理员列表：`GET /api/live/adjustments?status=&keyword=&page=&size=`。

审批：`POST /api/live/adjustments/{id}/review`

```json
{"result": "approve", "comment": "同意调整"}
```

`result` 只能是 `approve` 或 `reject`；驳回时 `comment` 至少 5 个字。

### 5.6 预约对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id | number | 预约编号 |
| bookingNo | string | 预约业务号 |
| farmerId / farmerName | number/string | 农户 |
| venueId / venueName | number/string | 场地 |
| deviceId / deviceNo / deviceName | number/string | 设备 |
| startTime / endTime | string | `yyyy-MM-dd HH:mm:ss` |
| topic | string | 直播主题 |
| status | string | `pending_review`、`approved`、`rejected`、`canceled`、`completed`、`no_show` |
| reviewComment | string/null | 审核意见 |
| recommendedTime | string/null | 推荐时间 |
| cancelReason | string/null | 取消原因 |
| products | array | 农产品清单 |
| createdAt | string | 创建时间 |

### 5.7 预约错误

| HTTP | code | 场景 |
|---|---|---|
| 400 | DEVICE_VENUE_MISMATCH | 设备不属于所选场地 |
| 400 | BOOKING_TIME_INVALID | 时段不合规 |
| 409 | BOOKING_CONFLICT | 场地或设备已被占用 |
| 409 | BOOKING_DUPLICATE | 同一农户同一时段已有预约 |
| 409 | CANCEL_WINDOW_CLOSED | 开播前 24 小时内取消 |
| 409 | BOOKING_STATUS_INVALID | 当前状态不能审核或取消 |

### 6.1 接口清单

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| POST | `/api/farmer/queues` | 农户 | 加入排队 |
| GET | `/api/farmer/queues` | 农户 | 我的排队 |
| GET | `/api/farmer/queues/slot-status` | 农户 | 时段状态查询（空闲 / 被占 / 自己占用） |
| POST | `/api/farmer/queues/{id}/confirm` | 农户 | 候补确认 |
| POST | `/api/farmer/queues/{id}/abandon` | 农户 | 放弃候补 |
| GET | `/api/live/queues` | 直播管理员 | 场地队列 |
| POST | `/api/live/queues/{id}/close` | 直播管理员 | 关闭队列 |

### 6.2 加入排队（已实现）

请求：

```json
{
  "venueId": 1,
  "startTime": "2026-11-01 10:00:00",
  "endTime": "2026-11-01 12:00:00"
}
```

规则：

- 时段必须已被他人预约占用才能排队（`SLOT_NOT_OCCUPIED` 空闲时段直接预约；`QUEUE_SELF_OCCUPIED` 自己占用的时段不能排队）；
- 按场地 + 时段排队，时段须整点、1-4 小时、不跨天、最多提前 30 天；
- 同一农户同一时段只能有一个有效排队，不区分场地；
- 开播前 24 小时内不能加入排队；
- 候补确认后又取消的，72 小时内不能对该场地排队（`QUEUE_COOLDOWN`）；
- 排队不保存主题与产品清单，候补确认生成的预约主题为"候补直播"；
- 排队号格式 `Q-农户编号-日期-序号`，序号按同一农户同一日期从 001 开始。

`GET /api/farmer/queues/slot-status?venueId=&startTime=&endTime=` 返回时段状态：
`occupied`（是否被有效预约占用）、`selfOccupied`（是否被自己占用）、`canJoin`（能否加入排队）、`queueCount`（当前排队人数）、`reason`（给农户看的说明）。

响应：排队对象，`status = queued`。

### 6.3 候补触发与确认（已实现）

晋升触发：

- 预约取消释放场地时，若该场地同时段无其他有效预约、至少 1 台设备可用且早于开播前 24 小时，队首自动 `queued → candidate`；
- 候选截止 = 开播前 24 小时，超时未确认自动 `expired` 并顺延下一位（每分钟扫描）；
- 到开播前 24 小时，仍未转正的 `queued` / `candidate` 统一关闭，不再发起候补（每分钟扫描）；
- 放弃、超时、确认后均顺延下一位。

`POST /api/farmer/queues/{id}/confirm`，无请求体：

- 只有 `candidate` 状态能确认；
- 确认时系统从该场地可用设备中分配一台；
- 确认成功生成 `approved` 预约并写入小时级资源锁；
- 没有可用设备时返回 409，候选资格保留到截止时间。

### 6.4 排队对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id | number | 排队编号 |
| queueNo | string | 排队号 |
| farmerId / farmerName | number/string | 农户 |
| venueId / venueName | number/string | 场地 |
| slotStart / slotEnd | string | 排队时段 |
| position | number | 当前顺位 |
| totalInQueue | number | 队列内有效人数 |
| estimatedWait | number | 预计等待场次（position - 1） |
| status | string | `queued`、`candidate`、`confirmed`、`expired`、`abandoned`、`closed` |
| candidateDeadline | string/null | 候补截止 |
| assignedDeviceId / assignedDeviceName | number/string/null | 确认后分配设备 |
| confirmedBookingId | number/null | 确认后预约 |
| createdAt | string | 入队时间 |

排队错误码：`QUEUE_DUPLICATE`（409 同一时段已有排队）、`QUEUE_COOLDOWN`（409 72 小时冷却）、`QUEUE_STATUS_INVALID`（409 状态不允许该操作）、`QUEUE_NO_DEVICE`（409 无可用设备）。

`GET /api/live/queues?venueId=&date=` 返回排队列表（含各队列组人数与顺位）；`POST /api/live/queues/{id}/close` 关闭该场地时段的整个队列组，组内 `queued`/`candidate` 全部置为 `closed`。

## 7. 通知接口（已实现）

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| GET | `/api/notifications` | 登录用户 | 本人通知（可按 type 筛选） |
| GET | `/api/notifications/unread-count` | 登录用户 | 未读数量 |
| POST | `/api/notifications/{id}/read` | 登录用户 | 标记已读 |
| GET | `/api/live/notifications` | 直播管理员 | 发送记录（可按 type/channel/status 筛选） |
| POST | `/api/live/notifications/{id}/retry` | 直播管理员 | 手动重试失败短信 |
| GET/POST/PUT/DELETE | `/api/live/notification-templates` | 直播管理员 | 模板增删改查 |

通知对象字段：

`id`、`type`、`eventKey`、`channel`、`title`、`content`、`status`、`retryCount`、`nextRetryAt`、`sentAt`、`read`、`readAt`、`createdAt`。

- `type`：`review`、`queue`、`candidate`、`reminder`、`device_fault`；
- `channel`：`in_app`、`sms`，同一事件各生成一条记录、分别记状态；
- `status`：`pending`、`sent`、`failed`、`final_failed`；站内即时送达即兜底；
- 短信为模拟网关，失败按 1/5/15 分钟重试三次后置 `final_failed`（调度每 30 秒扫描）；
- 开播前 1 小时提醒由调度每分钟扫描，同一预约只提醒一次（幂等）；
- 事件触发点：审核通过/驳回（review）、候补晋升（candidate）、顺位顺延（queue）、开播提醒（reminder）、设备停用/维修（device_fault，通知该设备未来已通过预约的农户）；
- 模板变量用 `${name}` 占位，白名单：`farmerName`、`topic`、`startTime`、`venueName`、`bookingNo`、`reviewComment`、`recommendedTime`、`deadline`、`position`、`deviceName`；变量缺失或不支持返回 400，不发送半截内容。

## 8. 销售与统计接口

### 8.1 销售录入

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| GET | `/api/live/sales` | 直播管理员 | 销售记录列表 |
| POST | `/api/live/sales` | 直播管理员 | 新增销售记录 |
| PUT | `/api/live/sales/{id}` | 直播管理员 | 修改销售记录 |
| DELETE | `/api/live/sales/{id}` | 直播管理员 | 删除销售记录 |

查询参数：`bookingId`、`keyword`、`page`、`size`。

请求：

```json
{
  "bookingId": 1,
  "productName": "草莓",
  "spec": "500g/盒",
  "quantity": 100,
  "unit": "盒"
}
```

规则：

- 预约必须是 `completed`；
- 数量大于 0，单位必填；
- 修改和删除要记日志；
- 一场直播同一农产品可以分规格录多条。

### 8.2 统计查询

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| GET | `/api/stats/overview` | 直播管理员、数据统计员、系统管理员 | 四项指标 |
| GET | `/api/stats/details` | 同上 | 完成场次明细 |
| GET | `/api/stats/export` | 同上 | 导出 CSV |
| GET | `/api/stats/trend` | 同上 | 趋势 |
| GET | `/api/stats/my` | 农户 | 本人数据（待开发） |

查询参数：

`from`、`to`、`countyCode`、`venueId`、`productName`、`page`、`size`；趋势另加 `granularity=day|week|month`。

`overview` 响应：

```json
{
  "occupancyRate": 60.0,
  "liveCount": 12,
  "soldQuantity": 350,
  "successRate": 80.0
}
```

口径：

- 场地占用率 = 已占用场地小时 ÷ 可开放场地小时 × 100%；
- 已占用按 `approved + completed` 的预约小时算；
- 直播场次只算 `completed`；
- 预约成功率 = `(approved + completed) ÷ 提交预约数`；
- 销售量按销售记录汇总。

## 10. AI 接口

### 10.1 知识库管理

| 方法 | 地址 | 角色 | 用途 |
|---|---|---|---|
| GET | `/api/live/knowledge-docs` | 直播管理员 | 文档列表 |
| POST | `/api/live/knowledge-docs` | 直播管理员 | 上传文档 |
| PUT | `/api/live/knowledge-docs/{id}/status` | 直播管理员 | 启用或停用 |
| DELETE | `/api/live/knowledge-docs/{id}` | 直播管理员 | 删除文档 |

上传使用 `multipart/form-data`：

- `file`：文字版 PDF、DOCX、MD、TXT，单文件 ≤20MB；
- `title`：标题。

文档字段：

`id`、`title`、`fileName`、`fileType`、`fileSize`、`parseStatus`、`enabled`、`version`、`createdAt`。

- `parseStatus`：`pending`、`parsing`、`parsed`、`failed`；
- 扫描件或图片 PDF 返回 400 `FILE_NOT_SUPPORTED`，提示“暂不支持扫描件”。

### 10.2 问答

`POST /api/ai/ask`

```json
{"question":"开播前多久可以改期？"}
```

响应：

```json
{
  "answer": "开播前 24 小时外可以申请调整。",
  "citations": [
    {"docTitle":"预约规则","section":"调整","page":3}
  ],
  "refused": false,
  "handoffAvailable": true
}
```

- 只回答知识库内容；
- 没有依据时 `refused=true`，回答“知识库暂无相关内容”；
- 不提交、不修改、不取消预约，不读农户业务数据。

### 10.3 转人工

`POST /api/ai/handoff`

```json
{"question":"我的预约异常，怎么处理？","answer":"","reason":"需要人工核实"}
```

返回转人工记录编号。

## 12. 常见错误

| 场景 | HTTP | code | 提示 |
|---|---|---|---|
| 未带令牌 | 401 | UNAUTHORIZED | 请先登录 |
| 令牌过期 | 401 | UNAUTHORIZED | 登录已过期，请重新登录 |
| 角色不匹配 | 403 | FORBIDDEN | 没有权限 |
| 缺二次验证票据 | 403 | TWO_FACTOR_REQUIRED | 请先完成二次验证 |
| 用户名重复 | 409 | CONFLICT | 用户名已存在 |
| 场地/设备冲突 | 409 | BOOKING_CONFLICT | 该时段已被占用 |
| 设备与场地不匹配 | 400 | DEVICE_VENUE_MISMATCH | 设备不属于该场地 |
| 取消窗口已关闭 | 409 | CANCEL_WINDOW_CLOSED | 开播前 24 小时内不能取消 |
| 重复排队 | 409 | QUEUE_DUPLICATE | 该时段已有排队 |
| 文件类型不支持 | 400 | FILE_NOT_SUPPORTED | 暂不支持该文件类型 |
| 参数为空 | 400 | BAD_REQUEST | 具体字段提示 |
