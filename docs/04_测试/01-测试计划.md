## 1. 目的与范围

### 1.1 目的
用最少但足够的测试，证明三件事：**业务规则对、并发不超卖、数据不泄露**。

### 1.2 范围

| 测 | 不测（说明） |
|---|---|
| 7 大模块 + RAG 的功能、边界、状态机 | 直播推流/交易/物流（范围外） |
| 预约—审核—排队—候补—通知全流程 | 第三方平台真实对接（可选，默认关闭） |
| 并发、性能、安全、兼容、易用性 | 原生 App/小程序 |
| 备份恢复、部署可复现 | 灾备机房切换（超出项目范围） |

### 1.3 质量目标（与 P0-05 一致）

- P0 需求覆盖率 100%，P0 用例通过率 100%；
- 遗留 P0 缺陷 0，P1 ≤2 且有规避；
- 预约提交 P95 ≤800ms；100 并发同段仅 1 成功；
- 越权 35 条 100% 拦截；敏感字段明文暴露 0；
- 注释率 ≥50%，核心单测覆盖率 ≥70%。

## 2. 测试策略

### 2.1 测试层级（V 模型）

| 设计层 | 测试层 | 载体 | 负责人 | 工具 |
|---|---|---|---|---|
| 业务需求 | 验收测试 / UAT | BDD 场景、UAT 脚本 | P1/P5 | 手工 + Playwright |
| 系统需求 | 集成/API 测试 | OpenAPI、RTM | P5 | REST Assured、Apifox |
| 高层设计 | 模块/组件测试 | 模块接口 | P4/P3 | JUnit、Vitest |
| 底层设计 | 单元测试 | 类/函数 | P4/P3 | JUnit、Vitest |
| 编码 | 静态检查/评审 | PR | P2 | Sonar、ESLint |

> 任一层缺测试 = 该层裸奔；RTM 中标出，G3 前补齐。

### 2.2 测试类型

| 类型 | 重点 | 时点 |
|---|---|---|
| 功能 | 主流程 + 异常 + 边界 | 每迭代 |
| 状态机 | 非法流转、并发审核 | S2/S3 |
| 并发 | 同段预约、排队、候补确认 | S3 |
| 性能 | 核心接口 P95、稳定性 | S4/S5 |
| 安全 | 越权、注入、脱敏、上传、注入 Prompt | S2 起持续，S5 专项 |
| 兼容 | 三浏览器 + 分辨率 | S3/S5 |
| 易用性 | UAT 任务完成率、SUS | W15 |
| 回归 | 上迭代 P0 用例 | 每迭代末 |
| 备份恢复 | 还原 + 数据校验 | W15 |

### 2.3 测试设计方法

- 等价类/边界值：时段、12h、72h、TTL、导出上限。
- 状态迁移：预约/排队/候补/调整。
- 场景法：预约—审核—排队—候补—通知。
- 错误猜测：重复提交、断网、超时、并发、越权。
- 判定表：审核通过/驳回条件组合。
- 正交：浏览器 × 分辨率 × 角色。

## 6. 缺陷管理

### 6.1 严重度与优先级

| 级别 | 定义 | 示例 | SLA |
|---|---|---|---|
| P0 | 主流程阻断/数据错误/安全漏洞 | 无法预约、超卖、越权看手机号 | 24h |
| P1 | 主要功能不可用但有规避 | 候补通知不发、导出失败 | 3 天 |
| P2 | 次要功能/体验 | 筛选不生效、文案错 | 本迭代 |
| P3 | 样式/建议 | 对齐、错别字 | 下迭代 |

### 6.2 流程

```text
新建（P5）→ 确认/定级（P5）→ 指派（P2）→ 修复 → 待验证 → 关闭
                                   ↘ 拒绝（理由）→ 复议（P1）
                                   ↘ 延期（P1 批准 + 风险登记）
```

### 6.3 缺陷单必填

标题、环境/版本、账号、复现步骤、期望/实际、证据（截图/日志/traceId）、关联 REQ/用例、严重度。

### 6.4 判定规则

- 需求理解不一致 → 以 SRS/规则为准；若文档不清，先改文档再判缺陷。
- 不可复现 → 补充证据，3 次仍不可复现转"观察"。
- 重复 → 关联主单，不重复计数。

## 7. 测试度量

| 指标 | 公式 | 目标 |
|---|---|---|
| 用例执行率 | 已执行/计划 | 100% |
| 用例通过率 | 通过/执行 | P0 100%，整体 ≥95% |
| 需求覆盖率 | 有用例的 REQ/总 REQ | 100% |
| 缺陷密度 | 缺陷数/千行代码 | 观察，不设硬指标 |
| 缺陷重开率 | 重开/关闭 | ≤10% |
| 缺陷逃逸率 | 上线后缺陷/总缺陷 | ≤5% |
| 平均修复时长 | Σ修复时长/缺陷数 | P0 ≤24h |
| 自动化率 | 自动化用例/总用例 | ≥30%（主流程 100%） |
| 阻塞时长 | 环境/构建不可用 | ≤2h/次 |

**测试报告模板**：

```markdown
## 第 N 迭代测试报告
- 范围：REQ 清单
- 环境/版本：
- 用例：计划 x / 执行 y / 通过 z（P0 通过率）
- 缺陷：新增 a / 关闭 b / 遗留 c（P0/P1/P2）
- 未通过项与原因：
- 性能/安全结论：
- 风险与建议：
- 结论：可发布 / 有条件发布 / 不可发布
```

## 8. UAT（用户验收测试）

| 项 | 安排 |
|---|---|
| 时间 | W15 |
| 对象 | 5–6 名同学（扮演农户/管理员），1 名客户代表 |
| 方式 | 观察 + 任务脚本 + 问卷 |
| 任务 | 预约、排队、候补确认、驳回后重约、手机端查看数据 |
| 指标 | 任务成功率 ≥90%；SUS ≥70；关键问题 ≤3 |
| 输出 | UAT 报告、改进项 ≥5 条、需求池更新 |

**UAT 规则**：只观察不引导；记录卡点与耗时；严重问题当场记录；不现场改代码。

## 9. 测试风险与应对

| 风险 | 应对 |
|---|---|
| 开发提测延迟 | 测试左移，用例先行；Mock 联调；调整回归优先级 |
| 环境不稳定 | 独立 test 环境；每日冒烟；故障 30 分钟响应 |
| 数据不真实 | 种子 + 工厂；边界数据专门构造 |
| 并发用例不稳定 | 固定时钟、隔离数据、重试 3 次仍失败才判缺陷 |
| 安全测试越界 | 仅测试环境、书面授权、只读优先 |
| 时间不足 | 按 P0→P1→P2 优先级执行，P2 可抽样 |
