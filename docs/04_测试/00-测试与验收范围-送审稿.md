## 1. 测试目标

用最少的测试，证明四件事：

1. **核心流程能走通**：预约 → 审核 → 排队/候补 → 通知。
2. **资源不冲突**：一个场地同一时段只成功一场，一台设备不被重复占用。
3. **数据不泄露**：手机号脱敏、无身份证和住址、越权访问被拦截。
4. **系统能交付**：能部署、能备份、能恢复、能验收。

## 4. 关键验收场景

### 4.1 场地与设备

- 一个场地同一时段只能成功一场；第二个预约被拒绝。
- 设备必须属于所选场地；选错场地或设备被拒绝。
- 场地可用但没有可用设备时，不能预约，提示“该场地暂无可用设备”。
- 设备维修、停用后，不出现在可约列表。
- 场地设备清单与设备所属场地一致。

### 4.2 预约与 24 小时边界

- 合法预约能提交，状态“待审核”。
- 非整点、跨天、少于 1 小时、超过 4 小时、早于 2 小时、超过 30 天，都被拒绝。
- 同一农户同一时段重复预约被拒绝。
- 开播前 24 小时外，可以取消；取消后场地释放。
- 开播前 24 小时内：
  - 可以提交新预约；
  - 农户不能取消；
  - 不能加入排队；
  - 停止候补；
  - 预约调整不能申请。
- 边界用固定时钟测：24 小时前 1 分钟、24 小时整、24 小时后 1 分钟。
- 预约调整：开播前 24 小时外可提交；同一预约只能有一条待审批；审批期间原预约保持“已通过”。
- 调整通过后换到新时段、新场地、新设备；驳回或撤销后原预约不变；只改农产品清单时场地设备不变。

### 4.3 排队与候补

- 同一场地同一时段，排队号唯一、顺位按申请时间。
- 同一农户同一时段只能有一个有效排队，不区分场地。
- 前序取消后，后序顺位前移。
- 场地释放且场地内有可用设备、时间早于开播前 24 小时，队首收到候补通知。
- 确认后分配一台设备，生成“已通过”预约。
- 放弃或超时后顺延下一位。
- 开播前 24 小时内停止候补，未转正排队关闭。
- 候补确认后又取消，72 小时内不能对该场地排队。

### 4.4 账号与权限

- 系统管理员能创建农户账号、重置密码；直播管理员没有开户入口。
- 农户首次登录必须改密码；停用农户不能登录。
- 农户只能看本人预约、排队、通知、个人数据。
- 直播管理员能建农户档案、上传和审核资质，但不能开账号、不能改角色、不能看系统日志。
- 数据统计员只能看和导出统计，不看单个农户明细。
- 未登录、越权访问管理页面被拒绝。
- 二次验证：不输验证码、输错、过期、连续 5 次错误都被拒绝；正确验证码能继续；失败有日志。

### 4.5 通知

- 审核结果、顺位变化、候补提醒、开播前 1 小时、设备故障五类事件都能触发。
- 站内消息能看到；设备故障同时发短信；关键通知不能关闭。
- 发送失败按 1、5、15 分钟重试 3 次；短信最终失败显示“最终失败（不再重试）”。
- 短信最终失败不影响站内兜底；站内兜底成功时农户仍能看到。
- 通知模板能新增、删除、修改、查询；停用后不再发送；未报备的短信模板不能启用。
- 通知模板变量缺失时发送失败并记录，不发送半截内容。

### 4.6 隐私与审计

- 列表、详情、导出默认显示手机号掩码。
- 系统管理员查看完整手机号要二次验证并留日志。
- 数据库和接口里没有身份证号、家庭住址字段。
- 关键操作有日志：审核、取消、强制取消、查看完整手机号、导出、改角色。
- 日志不能从业务界面修改或删除；系统管理员能按人、时间、类型查询日志，其他角色看不到。
- 直接改数据库日志能被防篡改校验发现并告警。

### 4.7 数据统计

- 场地占用率 = 已占用场地小时 ÷ 可开放场地小时 × 100%。
- 例：开放 10 小时、被占 6 小时 = 60%。
- 直播场次只算“已完成”。
- 每场直播卖出的农产品数量与录入明细一致。
- 预约成功率 =（已通过 + 已完成）÷ 提交预约数。
- 筛选条件变化后，指标和明细同步变化。
- 只有“已完成”的直播能录入销售；数量为 0、负数或单位为空被拒绝。
- 导入销售数据出错时能定位到第几行；修改销售记录有日志。
- 导出文件和页面字段一致；统计员看不到完整手机号。

### 4.8 AI 助手

- 文字版 PDF、DOCX、MD、TXT 能上传、查询、修改、删除、启用、停用；系统管理员只能查看。
- 扫描件或图片 PDF 提示“暂不能解析”，不能算解析成功。
- 规则问题回答带文档名和段落来源。
- 没有依据时明确拒答，不编造。
- 问“帮我取消预约”不产生任何业务操作。
- 问别人预约或手机号不能回答。
- 转人工有记录。
- 评测 50 个问题：前 5 条命中率 ≥85%、答案正确率 ≥80%、引用准确率 ≥90%、该拒答时拒答率 ≥85%。
- 模拟主模型不可用，能降级到备用模型、关键词或人工。

### 4.9 兼容与易用

- 电脑：Chrome、Edge 最新版，核心流程能完成。
- 手机网页：375、390、428 像素宽，核心流程能完成，不横向滚动。
- 用户试用 5–6 名同学，按任务脚本完成预约、取消、排队、候补、看通知；任务成功率 ≥90%，易用性评分 ≥70。

### 4.10 设备校准

- 设备到期前 7 天提醒直播管理员；同一设备同一到期日只提醒一次。
- 超过校准日期未校准，设备标记“待校准”。
- 待校准设备在列表和预约选择里有明显标记。

### 4.11 部署与恢复

- 从零部署能启动：Nginx、后端、MySQL、Redis、MinIO、AI 服务、Qdrant。
- 备份后能恢复：农户、场地、设备、预约、排队、日志、文件都能读。
- 重启后数据不丢；恢复后核心流程能走通。

## 5. 性能与并发验收

| 场景 | 通过标准 |
|---|---|
| 同一场地同一时段并发预约 | 100 个并发请求，只有 1 个成功，其余明确失败；无重复占用、无脏数据 |
| 同一场地同一时段并发排队 | 50 个并发请求，排队号唯一、顺位不重复、无重号 |
| 候补确认并发 | 同一候补名额只能 1 人确认成功，其他人失败并收到提示 |
| 预约提交 | 95% 请求在 800 毫秒内完成，成功率 ≥99% |
| 资源查询 | 95% 请求在 1.5 秒内完成 |
| 统计查询 | 95% 请求在 3 秒内完成 |
| 导出 5 万行 | 60 秒内完成，不内存溢出 |
| AI 问答首字 | 95% 请求在 5 秒内返回首字 |
| 稳定性 | 连续 2 小时混合负载，无内存溢出、无服务器错误增长 |

> 性能数据在测试环境测，不对生产做破坏性测试。

## 6. 缺陷分级与通过标准

### 6.1 缺陷分级

| 级别 | 定义 | 例子 |
|---|---|---|
| **阻断** | 核心流程走不通、数据丢失、隐私泄露、重复占用、越权 | 无法预约；同一场地两场都成功；手机号明文泄露；农户进管理后台 |
| **严重** | 主流程能走，但结果错、通知错、统计错 | 审核后状态不对；候补通知发错人；占用率算错 |
| **一般** | 不影响主流程，但影响使用 | 页面错位；筛选少一个条件；文字错误 |
| **建议** | 优化项 | 按钮位置、提示语、加载速度 |

### 6.2 验收通过标准

- 高优先级需求验收标准 **100% 通过**；
- 阻断缺陷 **0**；
- 严重缺陷 **0**；
- 一般缺陷有清单、有规避方案、不影响核心流程；
- 并发、性能、安全、备份恢复达到本标准；
- 用户试用达到任务成功率和易用性分数；
- 交付材料齐全。

> 中优先级功能允许“待优化”，但不能有阻断或严重缺陷；低优先级功能可以放到后续，不影响本次验收。

## 7. 测试环境与数据

| 项 | 方案 |
|---|---|
| 环境 | 测试环境做功能/回归；演示环境做性能/验收 |
| 数据库 | MySQL 8 独立库；每轮回归前重置 |
| 缓存 | Redis 独立库，不和生产共用 |
| 文件 | MinIO 测试桶；资质用假文件 |
| AI | Qdrant 测试集合；大模型可用测试额度或模拟 |
| 短信 | 测试环境用固定验证码或模拟发送 |
| 账号 | 四种角色各 2 个：正常、异常 |
| 数据 | 农户、场地、设备、预约、排队、通知、销售记录；全部假数据 |
| 时间 | 用固定时钟测 24 小时、72 小时、候补截止 |
| 隔离 | 每个用例独立数据，避免顺序依赖 |

**禁止**：用生产真实农户数据做测试；把真实手机号写进测试脚本；对生产做压测。

## 8. 验收流程

| 步骤 | 谁做 | 产出 |
|---|---|---|
| 1. 开发自测 | 前端、后端 | 单元测试、自测记录 |
| 2. 系统测试 | 测试人员 | 测试报告、缺陷清单 |
| 3. 性能与安全 | 测试人员 | 性能报告、安全报告 |
| 4. 界面与手机适配 | UI 设计师、测试人员 | 界面检查记录 |
| 5. 需求逐条验收 | 项目经理 | 验收清单 |
| 6. 用户试用 | 项目经理组织 | 试用记录 |
| 7. 部署与恢复 | 测试人员、后端 | 部署记录、恢复记录 |
| 8. 验收结论 | 项目经理 | 通过/待优化/不通过 |

**结论只有三档**：

- **通过**：可以交付；
- **待优化**：可以交付，但一般缺陷进清单，限期整改；
- **不通过**：阻断或严重缺陷未解决，不能交付。
