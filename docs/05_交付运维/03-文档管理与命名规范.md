## 2. 命名规范

### 2.1 目录

```text
docs/
├─ 00_项目管理/
├─ 01_需求/
├─ 02_设计/
├─ 03_开发规范/
├─ 04_测试/
├─ 05_交付运维/
├─ assets/
│  └─ prototypes/
└─ README.md
```

### 2.2 文件命名（本团队自定义，替代"类型+版本+日期"文件名）

**规则**：`<编号>-<名称>.md`

示例：

```text
01-需求规格说明书.md
02-业务规则与状态机.md
05-UI-UX设计规范.md
```

**为什么不在文件名里写版本和日期**：

- 文件名频繁变化会导致所有交叉链接失效（本项目 27 份文档互相引用超过 150 处）。
- 版本与日期写在**文档头部元信息 + 修订记录**，并由 Git 历史与 tag 保证可追溯。
- 对外交付/打印时，导出副本按 `<编号>_<名称>_v<版本>_<日期>.pdf` 命名。

> 原始要求允许"或本团队自定义文档规范"，此处为自定义规范，已在 G1 评审报备。

### 2.3 导出件命名

```text
R1-01_需求规格说明书_v1.0_20261019.pdf
P0-02_项目计划与迭代排期_v1.0_20261019.docx
```

### 2.4 版本号

| 变更 | 版本 |
|---|---|
| 初稿 | v0.1 |
| 评审后小改 | v0.2 |
| 基线/正式 | v1.0 |
| 基线后修订 | v1.1、v1.2 |
| 重大重构 | v2.0 |

- 每次修改必须更新头部版本与文末修订记录（版本/日期/修改人/说明）。
- 基线版本打 Git tag：`docs-v1.0`。

### 2.5 状态

| 状态 | 含义 | 可修改 |
|---|---|---|
| 草稿 | 编写中 | 作者 |
| 待评审 | 提交评审 | 仅修订 |
| 已批准 | 评审通过 | 走变更 |
| 基线 | 冻结 | 走 CCB |
| 已归档 | 历史版本 | 只读 |

## 4. 编写要求

| 要求 | 说明 |
|---|---|
| 一文档一主题 | 不把需求、设计、测试混在一份 |
| 结论先行 | 每节开头给结论，再展开 |
| 可判定 | 验收标准/阈值必须量化 |
| 有编号 | 需求 `REQ`、用例 `TC`、风险 `R`、决策 `ADR` |
| 有链接 | 引用其他文档用相对链接，不复制全文 |
| 有版本 | 头部 + 修订记录 |
| 有责任人 | 谁维护、谁审核 |
| 图表 | Mermaid 优先，随 Git 版本化；截图存 `assets/` |
| 语言 | 简体中文；术语统一（见 SRS §1.4） |
| 保密 | 不含真实手机号/密钥/生产地址 |

## 5. 评审与发布

```text
起草（作者） → 自检（清单） → 提交评审（P6 登记）
 → 评审会（相关角色） → 修订 → 批准（P1/P2）
 → 发布（仓库 + 语雀镜像） → 基线打 tag → 通知
```

### 5.1 评审类型

| 文档 | 评审人 | 频次 |
|---|---|---|
| 章程/计划/风险 | 发起人、P1、P2 | 里程碑 |
| SRS/规则/BDD | 全员 + 客户代表 | G1、变更时 |
| 架构/库表/API | P2/P3/P4/P5 | G1、接口变更 |
| UI 规范 | P1/P3/P6 | G1、迭代 |
| 测试计划/用例 | P1/P2/P5 | 迭代 |
| 交付文档 | P1/P5 | G5 |

### 5.2 发布检查

- [ ] 头部版本/日期/责任人已更新
- [ ] 修订记录已追加
- [ ] 交叉链接可打开（无死链）
- [ ] 编号与 RTM 一致
- [ ] 无敏感信息
- [ ] 已同步语雀镜像
- [ ] 已通知相关角色

## 6. 存储、同步与备份

| 项 | 规则 |
|---|---|
| 主存储 | Git 仓库 `docs/`（唯一事实源） |
| 镜像 | 语雀知识库（只读展示，周更） |
| 命名 | 与仓库一致，不加"最终版/最新" |
| 备份 | Git 远端 + 每月导出 PDF 归档 |
| 权限 | 全员可读；P1/P2/P6 可写；外部只读分享需 P1 批准 |
| 敏感文档 | 含账号/密钥的运维附件不入库，放密码管理器 |

**同步节奏**：每周五 P6 将 `docs/` 变更同步到语雀；G1/G5 前全量校对一次。

## 9. 归档与交付

- 交付时导出 PDF/DOCX 归档包（含目录、版本页、修订记录）。
- Git 仓库打 tag `v1.0.0` 与 `docs-v1.0`，保留只读镜像。
- 知识库源文件（PDF/DOCX）随 D05 交付，并附更新流程。
- 归档保留 5 年；含个人信息的文档按合规要求脱敏后归档。
