## 1. 验收原则

1. **可运行**：不是截图和 PPT，是能现场操作的系统。
2. **可复现**：全新环境按手册 30 分钟内启动。
3. **可追溯**：每个功能能指到 REQ、每个缺陷能指到用例。
4. **可交代**：代码、文档、数据、账号全部移交，不依赖个人。
5. **有边界**：范围外明确说明，不夸大、不隐藏已知问题。

## 4. 15 分钟演示脚本

> **准备**：生产/本地环境已启动；4 个账号；种子数据；浏览器标签预开；录屏备份。
> **原则**：先讲"痛点—做法—证据"，不逐页念功能。

| 时间 | 环节 | 操作 | 讲解要点 |
|---|---|---|---|
| 0:00–1:30 | 开场 | 首页/痛点图 | 三个痛点、五个目标、范围边界 |
| 1:30–4:00 | 农户预约 | 农户登录 → 填主题/产品 → 选时段 → 提交 | 3 步、整点/1–4h/提前 2h 校验 |
| 4:00–5:30 | 冲突与排队 | 用另一账号占同时段 → 再提交 → 进入排队 | 409 + 冲突资源 + 排队号/顺位 |
| 5:30–7:30 | 管理员审核 | 待审列表 → 驳回（原因+推荐时间）→ 通知 | 筛选、驳回必填、农户收到通知 |
| 7:30–9:30 | 排队与候补 | 取消预约 → 队首候补 → 倒计时确认 → 冷却提示 | FIFO、TTL、72h 冷却 |
| 9:30–11:00 | 统计与导出 | 指标卡 → 筛选 → 趋势 → 导出 Excel | 口径可复算、默认脱敏 |
| 11:00–12:30 | RAG | 问"开播前多久可改期" → 引用；问超范围 → 拒答/转人工 | 只读、引用、拒答、降级 |
| 12:30–14:00 | 权限与审计 | 农户访问他人数据 403；直播管理员仅见掩码；系统管理员看全号需二次验证；日志 | RBAC、脱敏、审计、哈希链 |
| 14:00–15:00 | 收尾 | 指标看板/测试数据 | 并发/性能/覆盖率/缺陷数据 |

### 4.1 演示兜底

| 故障 | 兜底 |
|---|---|
| 网络断 | 本地 Docker Compose 环境 |
| 服务挂 | 提前录屏（15 分钟） |
| 短信/LLM 不可用 | 切 Mock，说明降级链 |
| 数据被改乱 | 一键重置脚本 + 预置账号 |
| 时间不够 | 只演 1.5–9.5 分钟主链路，其余口头带过 |

## 5. 答辩 Q&A 准备（高频 14 问）

| # | 问题 | 回答要点 |
|---|---|---|
| 1 | 为什么用单体不用微服务？ | 6 人/16 周/强一致；模块化包边界 + 事件解耦；拆分路径已留（ADR-001） |
| 2 | 怎么保证不超卖？ | `resource_lock` 唯一约束是最终裁决；Redis 仅前置；100 并发压测仅 1 成功 |
| 3 | 排队公平吗？优先级会不会插队？ | 严格 `created_at,id` FIFO；优先级仅展示；压测无重号/无并位 |
| 4 | 候补 24h 太长怎么办？ | `min(24h, 开播前 2h)`；<30min 直接顺延；可配置 |
| 5 | 为什么确认后取消要冷却 3 天？ | 防止恶意占位；仅该设备；管理员可豁免并审计 |
| 6 | 手机号怎么保护？ | AES-GCM + HMAC 检索 + 掩码；全号需二次验证；无反向接口；日志脱敏 |
| 7 | 身份证/住址真的没有？ | 字段层不建；CI 扫描 information_schema；需求评审拦截 |
| 8 | RAG 胡说怎么办？ | 强制引用 + 阈值拒答 + 50 题评测 + 转人工；只读无写权限 |
| 9 | LLM/短信挂了怎么办？ | 多供应商 + FAQ 兜底 + 站内 + 人工；主流程不阻断 |
| 10 | 注释率 50% 是不是注水？ | cloc 统一口径；抽查"为什么"注释；无意义注释按缺陷处理 |
| 11 | 测试怎么证明测到位？ | RTM 81 需求 × 78 用例；P0 100%；边界/并发/越权/注入；断言强度自查 |
| 12 | 12 小时/72 小时边界怎么测？ | 固定时钟 + ±1 秒用例（TC-BOOK-12、TC-QUEUE-11） |
| 13 | 性能数据可信吗？ | staging 同构；数据量 20 万预约；JMeter 报告 + 慢 SQL + 监控截图 |
| 14 | 统计销量从哪来？ | V1 管理员录入/导入，页面标注来源；V1.1 对接销售系统（Q1） |
