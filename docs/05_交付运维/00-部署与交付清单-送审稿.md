## 1. 交付目标

交付不是“代码发过去”，而是做到四件事：

1. **能装**：全新服务器按手册能部署起来。
2. **能用**：核心流程能现场走通。
3. **能恢复**：数据备份能恢复，不是只备不验。
4. **能接手**：账号、文档、密钥、演示数据都交清楚，不依赖某个人。

---

## 2. 部署范围

### 2.1 部署结构

单台 Linux 服务器，容器化部署：

```text
用户浏览器
   ↓
Nginx（HTTPS、静态页面、反向代理、限流）
   ↓
后端应用（Java）
   ↓
MySQL / Redis / MinIO
   ↓
AI 服务（Python）→ Qdrant → 外部大模型
```

### 2.2 服务清单

| 服务 | 作用 | 对外端口 | 数据卷 |
|---|---|---|---|
| Nginx | 统一入口、静态页面、HTTPS | 80/443 | 证书、静态文件 |
| 后端应用 | 业务接口、权限、定时任务 | 不对外 | 日志 |
| MySQL | 业务数据、日志 | 不对外 | 数据目录 |
| Redis | 排队加速、缓存、限流 | 不对外 | 可持久化目录 |
| MinIO | 资质文件、知识库原文件 | 不对外 | 数据目录 |
| AI 服务 | 文档解析、检索、问答 | 不对外 | 日志 |
| Qdrant | 知识库向量 | 不对外 | 数据目录 |

> 只有 Nginx 对公网开放；数据库、缓存、文件、向量库、AI 服务都不直接暴露。

### 2.3 服务器要求

| 项 | 建议 |
|---|---|
| 操作系统 | Linux，Ubuntu 22.04 或同等级 |
| 配置 | 4 核 8G 起步；AI、Qdrant、MySQL 同机建议 8 核 16G |
| 磁盘 | 系统盘外，数据和备份单独留空间 |
| 网络 | 固定公网地址、域名、HTTPS 证书 |
| 时区 | Asia/Shanghai |
| 防火墙 | 只开 22、80、443；22 最好限制管理 IP；数据库等端口不对外 |

## 3. 部署包内容

| 内容 | 说明 |
|---|---|
| `docker-compose.yml` | 一次起 Nginx、后端、MySQL、Redis、MinIO、AI 服务、Qdrant |
| 后端镜像或构建文件 | Java 应用 |
| 前端构建产物 | 电脑管理端、手机网页静态文件 |
| AI 服务镜像或构建文件 | Python 服务 |
| Nginx 配置 | 静态页面、反向代理、HTTPS、限流 |
| 数据库脚本 | 建库、建表、初始数据、演示数据 |
| `.env.example` | 配置样例，不含真实密钥 |
| 部署说明 | 启动、停止、升级、回滚、排错 |
| 备份恢复脚本 | MySQL、MinIO、Qdrant、配置文件 |

**部署包不能包含**：真实密码、证书私钥、生产数据、个人手机号、身份证号、家庭住址。

## 4. 部署步骤

详细命令写在部署手册里，这里只定顺序：

1. **准备服务器**：系统更新、时区、防火墙、Docker、目录。
2. **放部署包**：解压到固定目录，比如 `/opt/farm/`。
3. **填配置**：复制 `.env.example` 为 `.env`，填数据库密码、Redis 密码、MinIO 账号、登录令牌密钥、短信和大模型配置。
4. **启动依赖**：MySQL、Redis、MinIO、Qdrant 先起，健康检查通过。
5. **初始化数据库**：建表、导入初始数据。
6. **启动后端和 AI 服务**：健康检查通过。
7. **启动 Nginx**：静态页面和反向代理生效。
8. **导入演示数据**：农户、场地、设备、预约、排队、知识库文档。
9. **冒烟测试**：按第 9 节的 8 项走一遍。
10. **交付确认**：记录部署时间、版本、账号、问题。

**部署通过标准**：全新服务器按手册一次部署成功，60 分钟内完成；第二次重复部署不失败。

## 5. 配置与密钥

| 配置 | 说明 |
|---|---|
| 数据库连接 | 地址、库名、账号、密码 |
| Redis 连接 | 地址、密码、库号 |
| MinIO | 地址、桶名、访问账号、密钥 |
| 登录令牌密钥 | 只放环境变量，不进代码 |
| 短信 | 短信服务地址、账号、模板编号 |
| 大模型 | 服务地址、密钥、模型名 |
| AI 服务 | Qdrant 地址、知识库集合名、超时时间 |
| 文件上传 | 单文件大小上限、允许类型 |

**规矩**：

- 密钥只放 `.env` 或服务器环境变量，不进代码仓库；
- `.env` 权限只给部署账号；
- 交付时给 `.env.example`，不给真实密钥；
- 密钥更换要记录，不能口头传。

## 6. 备份与恢复

### 6.1 备份什么

- MySQL：每日全量备份；
- MinIO：资质文件、知识库原文件；
- Qdrant：向量数据；
- 配置文件：Nginx、`.env`、Compose 文件；
- 版本号：镜像版本、代码版本。

### 6.2 备份要求

- 每日自动备份，至少保留 7 天；
- 备份文件不能只放同一块磁盘，至少异地一份；
- 备份要有记录：时间、大小、结果；
- 每季度做一次恢复演练。

### 6.3 恢复验收

- 在干净环境恢复 MySQL、MinIO、Qdrant；
- 能登录系统；
- 能查到农户、场地、设备、预约、排队、日志；
- 能打开知识库文档；
- 能走通一条预约流程；
- 恢复后数据与备份时点一致。

## 7. 监控与日志

不引入复杂的监控平台，先做够用的：

| 项 | 做法 |
|---|---|
| 健康检查 | 后端、AI 服务、MySQL、Redis、MinIO、Qdrant 都有健康检查 |
| 容器状态 | 挂了能自动重启；重启后记录 |
| 日志 | Nginx、后端、AI 服务日志按天切分，保留 30 天 |
| 磁盘 | 每天看剩余空间，低于 20% 告警 |
| 内存 | 每天看使用率，持续高于 85% 告警 |
| 备份 | 备份失败要告警 |
| 业务 | 预约失败率、通知失败率、AI 失败率异常时提醒管理员 |

**告警给谁**：系统管理员；系统管理员不在时给项目经理。

## 9. 交付验收标准

### 9.1 部署验收

- 全新服务器按手册一次部署成功，60 分钟内完成；
- 所有服务健康检查通过；
- 只有 Nginx 对公网开放；
- 重启服务器后系统能自动恢复；
- 第二次重复部署不失败。

### 9.2 冒烟测试 8 项

1. 四种角色都能登录，进入各自首页。
2. 系统管理员能创建农户账号；直播管理员能建农户档案、审资质。
3. 能建场地和设备，设备能归属场地。
4. 能提交预约，冲突时被拒绝。
5. 能审核通过/驳回，状态正确。
6. 能加入排队、确认候补、分配设备。
7. 能收到站内通知；短信失败有记录。
8. 能看统计、导出表格、问 AI 助手；AI 只回答文字知识库，不能改业务数据；扫描件 OCR 不在本期验收。

### 9.3 数据与安全验收

- 列表和导出手机号是掩码；
- 没有身份证号、家庭住址字段；
- 越权访问被拒绝；
- 日志能查、不能改；
- 备份能恢复；
- 交付包里没有真实密钥和生产数据。

### 9.4 文档验收

- 需求、设计、测试、部署、用户手册齐全；
- 文档版本与系统版本一致；
- 关键操作能按手册复现；
- 没有死链、没有空文件、没有“待补”。
