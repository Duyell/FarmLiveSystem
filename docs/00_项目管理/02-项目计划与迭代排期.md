## 1. 计划策略

1. **契约先行**：S0 冻结需求基线与 API 契约，前后端并行开发，减少联调等待。
2. **纵向切片**：每个迭代交付"可演示的端到端流程"，不做"只完成一层"的横向堆叠。
3. **测试左移**：P5 从 S1 介入，用例先于开发完成；每个 PR 必须有对应 REQ 与用例。
4. **风险前置**：并发冲突、短信/LLM 降级、脱敏合规在 S1–S2 就验证，不拖到最后。
5. **缓冲显性化**：W16 为唯一缓冲，任何人不得提前消耗；迭代内任务预留 15% 余量。

## 4. 关键路径

```
需求基线(M1) → 预约提交/冲突(S2) → 排队与候补(S3) → 统计口径(S4) → 系统测试(S5) → 交付(M7)
                     ↑                    ↑
              资源/权限(S1)        调整/取消(S3)
```

- **最长路径**：S0 → S2 预约冲突 → S3 排队候补 → S4 统计 → S5 测试 → 交付。
- **零浮动节点**：M1、M3、M4、M6、M7；任一延期直接压缩测试或交付。
- **可并行**：RAG（W12 起）与 S4 并行；UI 原型（W1–W2）与架构并行；文档（贯穿）。
