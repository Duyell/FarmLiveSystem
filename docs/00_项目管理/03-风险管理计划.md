## 1. 风险管理流程

```text
识别（周会/评审/回顾） → 分析（概率×影响） → 制定应对（规避/减轻/转移/接受）
      → 指派责任人 → 设定触发条件 → 监控（每周） → 关闭/升级
```

- **风险等级**：`分值 = 概率(1–5) × 影响(1–5)`；≥15 高（红）、8–14 中（黄）、≤7 低（绿）。
- **风险偏好**：合规与安全风险 **零容忍**；进度风险可接受 ≤1 周偏差；成本可接受 ≤20% 超支。
- **升级**：高风险连续 2 周未下降 → 升级到部门经理；触发条件命中 → 立即启动应急预案。

## 3. 专项风险预案

### 3.1 R02 并发超卖（最高技术风险）

**触发**：压测出现重叠占用，或代码评审发现"先查后写"。

**应急**：
1. 立即冻结 S2/S3 相关合并，回滚到最近可用版本。
2. 核对 `resource_lock` 是否存在重复有效行：
   ```sql
   SELECT resource_type, resource_id, slot_start, COUNT(*) c
   FROM resource_lock WHERE status='LOCKED'
   GROUP BY 1,2,3 HAVING c > 1;
   ```
3. 修复方向：唯一约束 + 固定锁顺序 + 乐观锁；禁止用应用层锁替代 DB 约束。
4. 回归：100 并发同段 + 审核/取消并发 + 候补确认并发三组脚本必须全绿。

### 3.2 R05 LLM 不可用（降级链）

```text
主：DeepSeek-V3 API
 ↓ 超时/429/5xx（重试 1 次，2s 超时）
备：通义千问 qwen-plus
 ↓ 仍失败
降级：关键词检索 FAQ（Top3）+ 固定话术
 ↓ 仍无结果
兜底：转人工工单 + 告知 24h 回复
```

- 用户可见提示："智能助手暂时繁忙，已为你切换到常见问题/人工通道"，**不暴露内部错误**。
- 监控：调用成功率 <95% 或 P95 >8s 触发告警（钉钉/邮件）。

### 3.3 R04 短信不可用

- 开发/测试：本地模拟网关（日志打印 + 管理页可查）。
- 生产：双供应商配置，失败自动切换；仍失败则站内兜底 + 管理员批量导出待通知清单人工电话。
- 禁止：因短信失败阻塞预约/审核主流程。

### 3.4 R06/R07 数据泄露与合规

- 上线前专项检查（详见 [D2-06](../02_设计/06-安全与合规设计.md) §9 合规清单）：
  - 数据库无身份证/住址/银行卡字段；
  - 列表、导出、日志中手机号均脱敏；
  - 无"反脱敏"接口；
  - 敏感操作 100% 二次验证 + 审计；
  - 隐私政策、授权记录、删除/导出通道可用。
- 一旦发现泄露：30 分钟内下线相关接口 → 评估影响范围 → 按法规告知 → 复盘。

### 3.5 R15 演示故障

- 准备三套演示介质：① 云上生产环境；② 本地 Docker Compose 一键启动；③ 录屏（15 分钟）。
- 演示前 24 小时冻结代码，彩排 2 次；准备离线种子数据与截图。
- 演示脚本见 [O5-02](../05_交付运维/02-交付物清单与验收标准.md)。
