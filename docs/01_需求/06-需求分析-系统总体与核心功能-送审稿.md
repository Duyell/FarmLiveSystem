## 1. 系统总体功能

### 1.1 系统定位

系统面向县域助农直播，管理农户、设备、场地、预约、排队、通知、统计和知识问答，让农户通过电脑或手机完成预约，让管理员在电脑上完成审核与资源调度。

### 1.2 模块总览

系统分 6 个业务模块 + 1 个 AI 助手，另有电脑端和手机网页两个入口。

| 模块 | 主要功能 | 主要使用角色 | 核心功能分级 | 核心功能阶段 |
|---|---|---|---|---|
| 基础信息 | 农户与资质、设备与场地、资源空闲查询、信息更新留痕 | 直播管理员、农户 | 高 | 第一阶段 |
| 直播预约 | 提交预约、冲突校验、审核、我的预约、取消 | 农户、直播管理员 | 高 | 第一阶段 |
| 排队与候补 | 排队号、顺位、候补确认/放弃/超时、冷却与重复限制 | 农户、直播管理员 | 高 | 第一阶段 |
| 通知 | 五类事件、站内与短信、失败重试 | 农户、直播管理员 | 高 | 第一阶段 |
| 数据统计 | 工作台概览 | 直播管理员、数据统计员、农户 | 高 | 第一阶段 |
| 权限管理 | 登录、四种角色、基础操作日志 | 系统管理员、直播管理员 | 高 | 第一阶段 |
| AI 助手 | 知识库维护、问答、引用、拒答、转人工、评测 | 农户、管理员 | 中 | 第二阶段 |
| 页面 | 电脑端、手机网页（H5 适配） | 全部角色 | 高 | 第一阶段 |

> 页面不是独立业务模块，是各模块的展示入口；电脑端和手机网页都要能用，手机网页（H5）是第一阶段必须完成的适配，不限制农户只用手机。
>
> 模块内的中、低优先级增强见第 3 节，不在这里重复。

### 1.3 四种角色与权限边界

> 四种角色是权限角色，这里只划权限，不规定由几个人担任。

| 角色 | 定位 | 使用入口 |
|---|---|---|
| 系统管理员 | 系统配置、账号角色、全量数据、操作日志 | 电脑管理端 |
| 直播管理员 | 农户资质、设备与场地、预约审核、排队管理、通知、统计 | 电脑管理端 |
| 农户 | 提交预约、查看本人预约、取消、排队、候补、通知、个人数据、问答 | 电脑或手机网页 |
| 数据统计员 | 查看和导出统计，不做业务操作 | 电脑管理端 |

#### 1.3.1 权限划分

| 功能或数据 | 系统管理员 | 直播管理员 | 农户 | 数据统计员 |
|---|---|---|---|---|
| 账号与角色（含农户账号） | 新增/删除/修改/查询（最高权限，日常不操作） | 无 | 无 | 无 |
| 系统配置 | 查看/修改 | 无 | 无 | 无 |
| 操作日志 | 查看/导出 | 无 | 无 | 无 |
| 农户与资质 | 查看全量 | 建档/编辑/审核 | 查看本人/上传本人资质 | 无 |
| 设备与场地 | 查看 | 新增/编辑/改状态/维修 | 查看可用资源 | 无 |
| 预约 | 查看全量 | 审核/调整审批/强制取消 | 提交/查看本人/取消/申请调整 | 无 |
| 排队与候补 | 查看 | 查看/关闭队列 | 加入/查看本人/确认/放弃 | 无 |
| 通知 | 查看全量/模板管理 | 查看/发送业务通知 | 查看本人 | 无 |
| 统计报表 | 查看/导出全量 | 查看/导出 | 查看本人数据 | 查看/导出 |
| 直播销售记录 | 查看 | 新增/修改/查询 | 无 | 查看/导出 |
| 知识库文档 | 查看 | 新增/删除/修改/查询 | 无 | 无 |
| AI 问答 | 可提问 | 可提问 | 可提问 | 可提问 |

> 手机号默认掩码；系统管理员查看完整号码要二次验证并留痕；数据统计员只看聚合统计，不看单个农户明细。
>
> 农户建档、资料维护和资质审核由直播管理员负责；农户账号由系统管理员在账号管理页面创建、重置或停用。
>
> 系统管理员对账号与角色有最高增删改查权限，但日常不操作业务数据，只在开号或异常处理时使用。
>
> 系统管理员在权限上拥有全部功能的最高增删改查；表中“查看全量”表示日常使用方式，不代表没有操作权限。日常业务由直播管理员操作，系统管理员只在异常或授权时介入。
>
> 表里写“无”的功能，任何入口都不能访问；系统管理员查看全量数据，也要遵守脱敏和审计规则。
>
> AI 问答这一行只表示角色可以提问，不代表能看业务数据；AI 助手只能查知识库、不改业务数据，具体见 3.8。
>
> 这张表是角色级的权限边界；更细的按钮和接口权限，在后续权限设计文档里展开。

### 1.4 场地与设备的关系

- **场地是主资源**：一个场地同一时段只能做一场直播。
- **设备属于场地**：一个场地可以有多台设备；一台设备只属于一个场地，设备表里存场地编号（场地ID）。
- **预约顺序**：先定场地和时段，再选该场地下的设备；设备必须属于这个场地。
- **场地设备清单**：由设备表按场地编号自动汇总，不手工另填一份。
- **可用条件**：场地开放、未被占用，并且场地内至少有 1 台可用设备，才能预约；候补只在开播前 24 小时之前发起。
- **设备归属**：本期设备固定归属一个场地，不随意换场地；确需更换，走变更并保留历史编号。

## 2. 核心流程

### 2.1 主流程

1. 农户在电脑或手机网页登录，填写县域、主题、时段、主推农产品，选择场地和时段，再从该场地下的可用设备中选择设备，提交预约。
2. 系统校验格式、时段和资源冲突：可用则进入“待审核”；冲突则提示“该时段已满”，农户可选择进入排队。
3. 直播管理员在电脑管理端审核：通过则锁定资源；驳回则填写原因和推荐时间。
4. 农户收到通知，可在“我的预约”查看状态；直播开始前可取消；需要改期可申请调整（第二阶段）。
5. 取消或调整释放场地后，系统按场地排队顺序通知候补人；候补人确认后，系统从该场地可用设备中分配一台设备；放弃或超时则顺延下一位。
6. 直播开始前 1 小时，系统提醒农户；直播结束后，管理员标记完成或未开播。

### 2.2 状态汇总

#### 2.2.1 预约、排队、通知、设备、农户

| 对象 | 状态 |
|---|---|
| 预约 | 待审核、已通过、未通过、已取消、已完成、未开播 |
| 排队 | 排队中、候补中、已确认、已过期、已放弃、已关闭 |
| 通知 | 待发送、已发送、发送失败（等待重试）、最终失败（不再重试） |
| 设备 | 可用、使用中、维修中、停用 |
| 农户 | 待审核、已认证、未通过、停用 |

> 状态只能按上面的方向流转，不能从“未通过”直接改成“已通过”，也不能从“已取消”改成“已完成”。
>
> 通知按渠道分别记状态；短信最终失败不代表站内失败，站内兜底成功时农户仍能看到消息。

#### 2.2.2 调整申请状态

| 调整申请状态 | 含义 |
|---|---|
| 待审批 | 农户提交了调整申请，管理员还没处理；原预约仍然有效 |
| 已通过 | 调整生效，预约换成新时段或新资源；预约状态仍然是“已通过” |
| 已驳回 | 调整不通过，原预约不变 |
| 已撤销 | 农户自己撤回调整，原预约不变 |

> 预约在调整审批期间保持“已通过”，不会出现“调整中”这个预约状态。
>
> 调整申请只能从“待审批”变为“已通过”“已驳回”或“已撤销”；结束后的申请不能再改。

## 3. 核心功能需求

> 每条需求写：谁用、做什么、输入输出、规则与异常、验收标准、分级和阶段。
> 分级只用高、中、低；阶段只用第一阶段、第二阶段。

### 3.1 基础信息

#### 需求 1.1 农户建档

- **谁用**：直播管理员。
- **做什么**：录入农户编号、姓名、所属县域、手机号、资质材料，形成农户档案。
- **输入/输出**：输入农户基本信息；输出农户档案，状态为待审核、已认证、未通过或停用。
- **规则与异常**：农户编号唯一；不能出现身份证号、家庭住址；手机号列表显示掩码；资质材料必须上传。
- **验收标准**：合法信息能建档；重复农户编号被拒绝；请求里出现身份证号或家庭住址被拒绝；列表手机号显示为“138****5678”。
- **分级/阶段**：高 / 第一阶段。

#### 需求 1.2 资质上传与审核

- **谁用**：农户上传，直播管理员审核。
- **做什么**：上传营业执照或农产品质检报告，管理员给出通过或未通过。
- **输入/输出**：输入 PDF、JPG、PNG，单文件不超过 10MB；输出资质状态。
- **规则与异常**：格式或大小不符要拒绝；未通过必须填原因；只有“已认证”的农户能提交预约。
- **验收标准**：超格式、超大小被拒绝；未通过不填原因被拒绝；未认证农户提交预约被拒绝；通过后农户状态变为已认证。
- **分级/阶段**：高 / 第一阶段。

#### 需求 1.3 设备与场地建档

- **谁用**：直播管理员。
- **做什么**：建立场地和设备档案，设备按“ZB-场地编号-设备序号”编号。
- **输入/输出**：输入场地名称、位置、容纳人数、开放时段；输入设备名称、型号、所属场地、校准周期；场地设备清单由设备自动汇总；输出场地与设备档案。
- **规则与异常**：设备编号自动生成且唯一；一个场地可以有多台设备，一台设备只属于一个场地；设备必须属于一个存在的场地；维修要填原因和预计恢复时间；维修中或停用的设备不能预约。
- **验收标准**：设备编号格式正确；绑定不存在的场地失败；场地设备清单与设备所属场地一致；维修设备不出现在可约列表；设备状态变更后列表同步。
- **分级/阶段**：高 / 第一阶段。

#### 需求 1.4 资源空闲查询

- **谁用**：农户、直播管理员。
- **做什么**：按日期和时段先查可用场地，再查该场地下的可用设备。
- **输入/输出**：输入日期、开始时间、结束时间、县域；输出可用场地，以及每个场地下的可用设备。
- **规则与异常**：先判断场地是否开放且未被占用，再看场地内是否有可用设备；场地可用但没有可用设备时要提示；维修中或停用的设备不算可用。
- **验收标准**：查询结果与实际占用一致；已占用场地不出现；场地可用但没有设备时提示“该场地暂无可用设备”；换一个时段能查到可用场地和设备。
- **分级/阶段**：高 / 第一阶段。

#### 需求 1.5 信息更新留痕

- **谁用**：直播管理员。
- **做什么**：修改农户资质或设备状态时，记录修改时间、原因和修改前后的值。
- **输入/输出**：输入修改内容和原因；输出变更记录。
- **规则与异常**：原因必填；历史记录不能删除；修改设备状态要同时记录状态变化。
- **验收标准**：不填原因不能保存；能查到修改人、时间、原因和前后值；连续修改三次能还原三个版本。
- **分级/阶段**：高 / 第一阶段。

| 编号 | 功能 | 说明 | 验收标准 | 分级/阶段 |
|---|---|---|---|---|
| 1.6 | 设备校准提醒 | 设备到期前 7 天提醒管理员；过期设备标记“待校准” | 同一设备同一到期日只提醒一次；过期状态能在设备列表看到 | 低 / 第二阶段 |

### 3.2 直播预约

#### 需求 2.1 提交预约

- **谁用**：农户，电脑或手机网页。
- **做什么**：填写所属县域、直播主题、直播时段、主推农产品，选择场地和时段，再从该场地下的可用设备中选择设备，提交预约；预约必须同时绑定 1 个场地和 1 台设备。
- **输入/输出**：输入主题、开始时间、结束时间、农产品清单、场地、该场地下的设备；输出预约号和“待审核”状态。
- **规则与异常**：时段必须是整点，1–4 小时，不跨天；开始时间至少晚于当前 2 小时，最多提前 30 天；农产品 1–20 项；同一农户同一时段只能有一场有效预约；县域必须与农户所属县域一致；设备必须属于所选场地；开播前 24 小时内仍可提交预约，但提交后不能取消，也不能进入候补。
- **验收标准**：合法提交成功并生成预约号；非整点、跨天、少于 1 小时、超过 4 小时、早于 2 小时、超过 30 天都被拒绝并说明原因；农产品为空或超过 20 项被拒绝；同一农户同一时段重复提交被拒绝；开播前 24 小时内提交的预约，取消时被拒绝。
- **分级/阶段**：高 / 第一阶段。

#### 需求 2.2 冲突校验与排队入口

- **谁用**：系统校验，农户选择是否排队。
- **做什么**：检查目标时段的设备和场地是否已被占用。
- **输入/输出**：输入提交的时段、设备、场地；输出冲突资源、排队入口和预计顺位。
- **规则与异常**：设备或场地任一小时重叠就算冲突；冲突时不能产生第二条占用记录；农户确认后才生成排队。
- **验收标准**：冲突时返回具体冲突资源；同一时段不会出现两条有效占用；农户能看到“进入排队”入口；不确认排队时不产生排队记录。
- **分级/阶段**：高 / 第一阶段。

#### 需求 2.3 预约审核

- **谁用**：直播管理员。
- **做什么**：查看待审核预约，选择通过或驳回。
- **输入/输出**：输入审核结果、驳回原因、推荐时间；输出预约状态和通知。
- **规则与异常**：驳回必须填至少 5 个字的原因，并给出一个可预约的推荐时间；推荐时间不能和已有占用冲突；通过后锁定设备和场地；同一预约不能重复审核。
- **验收标准**：驳回不填原因或推荐时间被拒绝；推荐时间冲突被拒绝；通过后资源被锁定；农户收到审核结果通知；重复审核被拒绝。
- **分级/阶段**：高 / 第一阶段。

#### 需求 2.4 我的预约与状态

- **谁用**：农户。
- **做什么**：查看本人预约列表和详情，包括审核意见和推荐时间。
- **输入/输出**：输入状态、时间范围；输出本人预约列表和详情。
- **规则与异常**：只能看本人预约；不能通过改地址看别人的预约；状态和审核意见要准确。
- **验收标准**：列表只显示本人预约；改地址查别人预约被拒绝；驳回的预约能看到原因和推荐时间；状态与管理员操作一致。
- **分级/阶段**：高 / 第一阶段。

#### 需求 2.5 取消预约

- **谁用**：农户、直播管理员。
- **做什么**：取消预约，填写原因，释放场地并触发候补。
- **输入/输出**：输入取消原因；输出“已取消”状态和资源释放结果。
- **规则与异常**：开播前 24 小时内，农户不能取消；原因必填；管理员因设备故障或场地不可用可以强制取消，要二次确认并记录原因；取消后要通知排队人。
- **验收标准**：取消后场地可以再次被预约；队首候补人收到通知；开播前 24 小时内农户取消被拒绝；管理员强制取消有记录。
- **分级/阶段**：高 / 第一阶段。

#### 需求 2.6 预约调整

- **谁用**：农户申请，直播管理员审批。
- **做什么**：修改时段、设备、场地或农产品清单，审批通过后生效。
- **输入/输出**：输入调整内容、原因；输出调整申请和“待审批”状态。
- **规则与异常**：开播前 24 小时可申请；审批期间原预约保持“已通过”；调整申请状态为待审批、已通过、已驳回、已撤销；新时段冲突时不能通过；调整后的设备必须属于调整后的场地；同一预约同时只能有一条待审批调整。
- **验收标准**：24 小时内申请被拒绝；调整审批期间预约状态仍是“已通过”；通过后资源换绑且预约状态仍为“已通过”；驳回或撤销后原预约不变；新时段冲突时审批失败；设备与场地不匹配时审批失败。
- **分级/阶段**：中 / 第二阶段。

#### 需求 2.7 完成与未开播标记

- **谁用**：直播管理员。
- **做什么**：直播结束后，把预约标记为“已完成”或“未开播”。
- **输入/输出**：输入完成结果，未开播时填写原因；输出预约状态。
- **规则与异常**：只有已开始的预约才能标记；未开播必须填原因；标记完成后不能再取消。
- **验收标准**：状态能正确变为已完成或未开播；未开播不填原因被拒绝；统计里的直播场次只算已完成。
- **分级/阶段**：中 / 第二阶段。

### 3.3 排队与候补

#### 需求 3.1 加入排队与排队号

- **谁用**：农户。
- **做什么**：资源冲突时确认进入排队，生成排队号和顺位。
- **输入/输出**：输入冲突的预约信息；输出排队号、当前顺位和预计等待场次。
- **规则与异常**：同一农户、同一场地、同一时段只能有一个有效排队；同一农户同一时段也只能有一个有效排队，不区分场地；排队号按“Q-农户编号-日期-序号”生成，序号按同一农户同一日期从 001 开始且唯一；开播前 24 小时内不能加入排队。
- **验收标准**：排队号格式正确；同一场地重复排队被拒绝并显示已有排队号；同一农户同一时段在两个场地排队，第二次被拒绝；同一农户同一天多次排队，序号递增不重复；开播前 24 小时内加入排队被拒绝；顺位按申请时间排序；取消后序号不复用。
- **分级/阶段**：高 / 第一阶段。

#### 需求 3.2 顺位与查询

- **谁用**：农户、直播管理员。
- **做什么**：查看当前顺位、总人数和预计等待场次。
- **输入/输出**：输入日期、场地；输出顺位、总人数和预计等待场次。
- **规则与异常**：严格先来先到；前序取消后后序自动前移；农户只能查本人排队。
- **验收标准**：第 3 位显示“预计等待 2 场”；前序取消后 5 秒内变为第 2 位；农户看不到别人的排队详情。
- **分级/阶段**：高 / 第一阶段。

#### 需求 3.3 候补确认、放弃与超时

- **谁用**：农户、直播管理员。
- **做什么**：场地释放后通知队首，农户在规定时间内确认或放弃；确认后从该场地可用设备中分配一台设备。
- **输入/输出**：输入候补通知；输出确认后的预约、放弃记录或超时记录。
- **规则与异常**：只通知队首；场地释放、场地内至少有 1 台可用设备，并且当前时间早于开播前 24 小时，才发起候补；确认截止时间就是开播前 24 小时；确认后分配一台可用设备并生成“已通过”预约；确认时设备临时不可用要提示，候选资格保留到截止时间；放弃或超时后顺延下一位；开播前 24 小时内停止候补，不再发起新的候补；到开播前 24 小时仍未转正的排队统一关闭；每次操作都留记录。
- **验收标准**：场地释放且设备可用、时间早于开播前 24 小时时，队首收到通知；确认后预约成功并分配设备；放弃后下一位收到通知；到开播前 24 小时未确认自动过期并顺延；开播前 24 小时内停止候补；记录包含选择结果和时间。
- **分级/阶段**：高 / 第一阶段。

#### 需求 3.4 冷却与重复限制

- **谁用**：农户、直播管理员。
- **做什么**：限制同一农户对同一场地的重复排队，以及候补确认后又取消的行为。
- **输入/输出**：输入排队或取消操作；输出允许、拒绝和解禁时间。
- **规则与异常**：同一农户、同一场地、同一时段只能排队一次；候补确认后又取消，72 小时内不能对该场地排队；其他场地不受影响。
- **验收标准**：重复排队被拒绝；冷却期内排队被拒绝并显示解禁时间；冷却期后可以再排队；其他场地正常。
- **分级/阶段**：高 / 第一阶段。

### 3.4 通知

#### 需求 4.1 五类事件通知

- **谁用**：系统发送，农户和管理员接收。
- **做什么**：在审核结果、顺位变化、候补提醒、开播前 1 小时、设备故障五个节点发送通知。
- **输入/输出**：输入事件；输出站内消息、短信和发送状态。
- **规则与异常**：设备故障优先短信；关键通知不能关闭；站内消息必须能看到；短信失败要记录。
- **验收标准**：五类事件都能触发；关键通知在站内可见；设备故障同时发短信；发送失败有状态记录。
- **分级/阶段**：高 / 第一阶段。

#### 需求 4.2 发送失败重试

- **谁用**：系统。
- **做什么**：短信或站内消息发送失败后自动重试，仍失败则兜底。
- **输入/输出**：输入发送失败；输出重试记录、每个渠道的最终状态和站内兜底消息。
- **规则与异常**：短信和站内消息分开记状态；失败后 1、5、15 分钟各重试一次，最多 3 次；同一事件同一渠道不能重复发送；重试仍失败要通知管理员，短信最终失败不影响站内兜底。
- **验收标准**：失败后能看到 3 次重试；短信最终失败显示“最终失败（不再重试）”；管理员收到提醒；站内兜底成功时农户仍能看到消息。
- **分级/阶段**：高 / 第一阶段。

### 3.5 登录与角色权限

#### 需求 5.1 登录

- **谁用**：全部角色。
- **做什么**：用账号、密码和验证码登录，进入对应角色的首页。
- **输入/输出**：输入账号、密码、验证码；输出登录结果和角色信息。
- **规则与异常**：连续 5 次密码错误锁定 15 分钟；登出后旧登录失效；停用账号不能登录。
- **验收标准**：正确账号能登录；5 次错误被锁定；登出后不能继续访问；停用账号登录被拒绝。
- **分级/阶段**：高 / 第一阶段。

#### 需求 5.2 四种角色

- **谁用**：系统管理员分配，全部角色使用。
- **做什么**：按系统管理员、直播管理员、农户、数据统计员四种角色控制菜单、按钮和数据范围。
- **输入/输出**：输入角色；输出可见菜单、可操作按钮和可查看数据。
- **规则与异常**：权限边界见 1.3.1；农户只能看本人数据；直播管理员负责农户建档、资质审核与资源管理，不建账号；系统管理员对账号与角色有最高权限，农户账号由其在账号管理页面创建，但日常不操作业务数据；数据统计员只能看和导出统计。
- **验收标准**：农户看不到管理菜单；统计员不能做业务操作；直播管理员能建档和审核，但不能改角色、不能开农户账号；系统管理员在账号管理页面能创建农户账号，并能查看全量数据。
- **分级/阶段**：高 / 第一阶段。

#### 需求 5.3 农户账号开户

- **谁用**：系统管理员在账号管理页面创建，农户使用。
- **做什么**：为已建档的农户创建登录账号，生成初始密码；农户首次登录必须改密码。
- **输入/输出**：输入农户编号和手机号；输出账号、初始密码和账号状态。
- **规则与异常**：只有系统管理员能创建农户账号；一个农户只能有一个账号；农户不能自助注册；账号停用或农户停用后不能登录；系统管理员可以重置密码。系统管理员日常不操作业务数据，只在开号或异常处理时进入账号页面；直播管理员不建账号。
- **验收标准**：系统管理员在账号页面创建后农户能登录；首次登录必须改密码；重复创建被拒绝；直播管理员没有开户入口；停用农户不能登录。
- **分级/阶段**：高 / 第一阶段。

### 3.6 基础审计与脱敏

#### 需求 6.1 操作日志

- **谁用**：系统记录，系统管理员查看。
- **做什么**：记录操作人、角色、时间、操作内容、网络地址。
- **输入/输出**：输入业务操作；输出操作日志。
- **规则与异常**：审核、删除、查看完整手机号、导出等关键操作必须记录；日志不能修改或删除；支持按操作类型和时间查询。
- **验收标准**：关键操作都有日志；日志包含操作人、角色、时间、内容和网络地址；能按类型和时间查询；普通用户看不到日志。
- **分级/阶段**：高 / 第一阶段。

#### 需求 6.2 手机号脱敏

- **谁用**：全部角色。
- **做什么**：列表、详情、导出默认显示掩码；本人和系统管理员可看完整号码。
- **输入/输出**：输入查看请求；输出掩码或完整号码。
- **规则与异常**：列表和导出默认掩码；系统管理员看完整号码要二次验证、填写原因并留日志；系统不提供“输入掩码反查完整号码”的功能。
- **验收标准**：列表显示“138****5678”；他人看不到完整号码；系统管理员查看完整号码有审计记录；不存在反查功能。
- **分级/阶段**：高 / 第一阶段。

#### 需求 6.3 禁止存储身份证号和家庭住址

- **谁用**：系统。
- **做什么**：农户信息中不设身份证号、家庭住址字段，提交时直接拒绝。
- **输入/输出**：输入农户信息；输出保存成功或拒绝。
- **规则与异常**：数据库不建这两个字段；请求里出现这两个字段时拒绝，不落库。
- **验收标准**：提交含身份证号或家庭住址被拒绝；数据库里找不到这两个字段；正常农户信息不受影响。
- **分级/阶段**：高 / 第一阶段。

### 3.7 数据统计

#### 需求 7.1 工作台概览

- **谁用**：直播管理员。
- **做什么**：登录后看到待审核预约、今日直播、资源概况。
- **输入/输出**：输入登录；输出待办数量、今日直播列表、设备与场地概况。
- **规则与异常**：数字要和列表一致；没有数据时显示 0 或“暂无”。
- **验收标准**：待审核数量与审核列表一致；今日直播能点进详情；资源概况能看到可用、维修、停用数量。
- **分级/阶段**：高 / 第一阶段。

#### 需求 7.2 四项核心指标与导出

- **谁用**：直播管理员、数据统计员。
- **做什么**：统计场地占用率、农户直播场次、每场直播卖出的农产品数量、预约成功率，支持按时间、县域、农产品类型筛选并导出表格。
- **输入/输出**：输入时间、县域、农产品类型；输出指标卡、明细和表格文件。
- **场地占用率口径**：已占用场地小时 ÷ 可开放场地小时 × 100%；已占用按“已通过 + 已完成”的预约小时算，可开放按场地开放时段内、场地状态正常的小时算；设备维修不影响这个分母。
- **预约成功率口径**：（已通过 + 已完成）÷ 提交预约数 × 100%；提交预约数不含排队记录，驳回和取消仍计入分母。
- **规则与异常**：四个指标要能按明细复算；直播卖出数量按已完成场次由直播管理员录入或导入，系统不自动抓取订单；没有数据时显示 0；导出文件和页面字段一致。
- **验收标准**：直播管理员能按场次录入或导入卖出的农产品数量；汇总数与明细一致；场地占用率抽样复算一致（例：开放 10 小时、被占 6 小时 = 60%）；抽样 10 条能手工复算一致；筛选条件变化后结果变化；导出文件能打开且字段一致；没有数据不报错。
- **分级/阶段**：中 / 第二阶段。

> “每场直播卖出的农产品数量”是指：直播结束后，管理员按场次录入或导入的实际销售数量（件、斤、箱等），不是系统自动从订单抓取；没有录入时统计为 0 或“暂无”。
>
> 例：场地每天开放 10 小时，已通过和已完成预约共占 6 小时，场地占用率 = 60%。

### 3.8 AI 助手

#### 需求 8.1 知识库维护

- **谁用**：直播管理员（新增、删除、修改、查询）；系统管理员（查看）。
- **做什么**：维护预约规则、溯源资料、常见问题等知识库文档，系统解析后存入知识库。
- **输入/输出**：输入 PDF、DOCX、MD、TXT，单文件不超过 20MB；输出文档状态和知识库内容。
- **规则与异常**：解析失败要说明原因；文档可以启用、停用；停用后不再被检索；系统管理员只能查看，不能改内容。
- **验收标准**：支持格式能新增成功；能删除、修改、查询文档；损坏文件显示失败原因；停用后问答查不到该文档；启用后能查到。
- **分级/阶段**：中 / 第二阶段。

#### 需求 8.2 问答、引用、拒答、转人工

- **谁用**：农户、管理员。
- **做什么**：用自然语言问预约规则、排队规则、农产品溯源等问题。
- **输入/输出**：输入问题；输出回答、来源引用、拒答提示或转人工入口。
- **能力边界**：AI 助手是只读的——只能查知识库并回答，不能提交、修改、取消预约，不能改排队、候补和农户资料，也不能查看农户业务数据。
- **规则与异常**：只回答知识库里的内容；回答要带来源；没有依据时明确说“知识库暂无相关内容”，不能编造；答不上来可转人工。
- **验收标准**：规则问题回答带来源；没有依据的问题明确拒答；说“帮我取消预约”不产生任何业务操作；转人工能生成记录。
- **分级/阶段**：中 / 第二阶段。

| 编号 | 功能 | 说明 | 验收标准 | 分级/阶段 |
|---|---|---|---|---|
| 8.3 | AI 助手评测与版本 | 用 50 个问题测回答质量；知识库版本可回滚 | 正确率、引用准确率、拒答率达到约定值；回滚后能查到旧版内容 | 低 / 第二阶段 |

### 3.9 页面

#### 需求 9.1 农户端页面（电脑 + 手机网页）

- **谁用**：农户。
- **做什么**：在电脑或手机网页完成登录、预约、查看我的预约、取消、排队、候补确认、看通知、看个人数据、问 AI 助手。
- **输入/输出**：输入电脑或手机操作；输出页面和操作结果。
- **规则与异常**：页面适配 375–428 像素宽；不能横向滚动；按钮要能点到；网络失败要有提示。
- **验收标准**：电脑和手机网页都能完成预约全流程；取消和候补确认能操作；通知能看到；手机页面不横向滚动。
- **分级/阶段**：高 / 第一阶段。

#### 需求 9.2 电脑管理端

- **谁用**：直播管理员、系统管理员、数据统计员。
- **做什么**：在工作台、农户、资质、设备、场地、预约审核、排队、通知、统计、角色、日志、AI 知识库等页面完成管理工作。
- **输入/输出**：输入管理操作；输出列表、详情和操作结果。
- **规则与异常**：列表要能筛选和分页；关键操作要有确认；没有权限的菜单不显示。
- **验收标准**：管理员能完成审核、资源管理、排队管理和统计查看；统计员只能看和导出；系统管理员能管账号和日志。
- **分级/阶段**：高 / 第一阶段。

## 5. 已确认的口径

| # | 问题 | 结论 |
|---|---|---|
| 1 | “每场直播卖出的农产品数量”怎么算？ | 直播结束后，直播管理员按场次录入或导入的实际销售数量（件、斤、箱等）；系统没有订单模块，不自动抓取；没有录入时统计为 0 或“暂无”。 |
| 2 | 预约是否绑定场地与设备？ | 必须同时绑定 1 个场地 + 1 台设备；设备必须属于该场地。 |
| 3 | 候补、取消和新预约的时间边界？ | 候补必须在开播前 24 小时前确认；开播前 24 小时内停止候补，农户不能取消，但仍可提交新预约；到开播前 24 小时仍未转正的排队统一关闭。 |
| 4 | 排队号里的“序号”按什么范围排？ | 同一农户同一日期从 001 开始；同一农户同一时段只能有一个有效排队。 |
| 5 | “场地占用率”怎么算？ | 已占用场地小时 ÷ 可开放场地小时 × 100%；按场地算，不按设备算。 |
| 6 | “预约成功率”怎么算？ | （已通过 + 已完成）÷ 提交预约数 × 100%；提交预约数不含排队记录。 |

> 管理员因设备故障或场地不可用需要强制取消的，保留异常处理入口；如果你要求管理员也不能取消，告诉我。
